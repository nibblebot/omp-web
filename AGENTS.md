# AGENTS.md

Orientation for agents working in this repo. Read before editing. README.md is the user-facing doc; this file is the engineering map: commands, layout, wire contract, invariants, conventions, verification.

## What this repo is

Two products in one tree, sharing one Solid.js web UI and one wire contract:

- **omp-session** (`apps/session/`): the session daemon. One process, one project dir (bound at spawn, immutable), one live agent session via the `@oh-my-pi/pi-coding-agent` SDK **in-process** (`createAgentSession`: no child process, no JSON-RPC hop). Serves the wire API only (SSE `/events`, `POST /command`, the collab WS relay, `/download`); it serves no web UI (`apps/fleet/edge.ts` is the only UI server).
- **omp-fleet** (`apps/fleet/`): registry + supervisor + connector for N daemons (local children, external/remote), and the only server of the web UI. Re-exposes the daemons to the browser UI it serves and to CLI fan-out. Holds **zero agent state**. All truth lives in the omp-session processes and their `.jsonl` session logs.
- **Web UI** (`apps/web/`): one Solid.js bundle served by the fleet edge. A page that receives an `attached`/`hello_ok` frame before any `roster` frame was pointed at a bare session daemon, so it sets `state.fleetRequired` and renders the fleet-required notice (`FleetRequiredNotice`) instead of the shell. No router.

Repository layout: `apps/{cli,fleet,session,web}` hold the applications (production source flat directly inside `apps/cli`, `apps/fleet`, and `apps/session`; `apps/web` keeps its existing component/feature hierarchy), `lib/{wire,platform,runtime,session-files,sdk-settings,testkit}` holds the closed shared libraries, `e2e/` holds cross-app and distribution end-to-end tests, and tests live under their owner's `test/` (`apps/*/test`, `lib/*/test`, tooling tests under `scripts/test/`).

Runtime is **Bun** (`type: module`, `bun.lock` committed). GitHub Actions is used only to build and deploy the docs site from `main` (`.github/workflows/docs.yml`); there is no product CI. Lint runs the closed-library boundary check first (`scripts/check-lib-boundary.ts`: every resolved repository import from `lib/` must stay inside `lib/`, and library cycles fail) and then **oxlint** (`.oxlintrc.json`; Solid rules come from `eslint-plugin-solid` loaded as an oxlint JS plugin); formatting runs through **oxfmt** (`.oxfmtrc.json`: tabs, print width 100, TS/TSX only: markdown/CSS/HTML/JSON stay hand-maintained). Comments reference audit findings as `finding #N` (numbering kept from the 2026-08 audit).

## Commands

```sh
bun install                    # once; resolves the exact @oh-my-pi/* pins in bun.lock (no dependency patches)
bun run dev                    # vite (HMR, /events+/command proxied to the fleet edge) + omp-fleet, no automatically managed auth broker; stable per-worktree vite port, ephemeral fleet port; opens the UI in a browser on interactive runs (--open/--no-open); fleet state/lock scoped per worktree under the data home (dev-fleets/<slug>-<hash8>/), so N worktrees + the user's real fleet coexist; config and managed workspaces stay shared
bun run dev --auth-broker      # opt into authenticated broker adoption on 127.0.0.1:8765 (not managed), or spawn `omp auth-broker serve` as a restartable child; exports OMP_AUTH_BROKER_URL/OMP_AUTH_BROKER_TOKEN for profile secretRefs `env:` references; broker setup failure warns rather than failing the stack
bun run dev:server             # just the daemon, --watch
bun run dev:web                # just vite
bun run check:types            # tsgo -p tsconfig.json --noEmit  (tsgo = @typescript/native-preview, NOT tsc)
bun run lint                   # scripts/check-lib-boundary.ts + oxlint (.oxlintrc.json); oxlint warnings only don't fail the run
bun run format                 # oxfmt, writes in place (TS/TSX only)
bun run format:check           # oxfmt --check, exits nonzero on unformatted files
bun run test                   # scripts/test.ts wrapper → bun test (see Testing)
bun scripts/test.ts --bail 1   # extra args forwarded to bun test (file filters work: `bun scripts/test.ts apps/session/test/omp-session.test.ts`)
bun run build                  # → dist-bundle/cli.js installable bundle (vite build → regenerate apps/fleet/embedded-dist.ts → bun build, dist/ + @oh-my-pi/* external; shebang verified)
bun run build:web              # vite build → dist/ (gitignored; the UI half of `build`)
bun run dev:docs               # Astro/Starlight docs site under docs/, served with the /omp-web/ base
bun run build:docs             # static docs build → docs/dist/ for GitHub Pages
bun run preview:docs           # preview the built docs site locally
bun e2e/onboarding.ts           # OFFLINE distribution+onboarding E2E, the last command of the release gate: pack → poisoned-store pinned install → first-run config → bare serve → spawn → update round-trip (exit 0 = green)
bun scripts/preflight.ts       # release drift report (advisory and standalone: the orchestrator never calls it). Errors: intra-set @oh-my-pi/* pin mismatch. Warnings: pins behind upstream npm latest, unpushed commits, gh auth, unchecked docs boxes, dead relative doc links, documented gate list vs GATE_COMMANDS, stale SDK version literals. ```
```

Broker management is opt-in only via `bun run dev --auth-broker`: default `dev`, `dev:server`, and `dev:web` do not create broker tokens, probe, adopt, spawn, restart, or automatically export broker variables. Explicit user-supplied `OMP_AUTH_BROKER_URL`/`OMP_AUTH_BROKER_TOKEN` and provider-profile `secretRefs` remain inherited opt-in configuration. Production `omp-web` never manages broker startup. Local sessions use the user's ordinary SDK credentials; isolated clone sandboxes require explicitly configured credentials or an operator-run broker injected through profile `secretRefs`.

Ports: defaults vite **4713**, omp-session **4721**, omp-fleet **4722** (used by `dev:web`/`dev:server`/`fleet -- serve` run directly). The `dev` runner instead chooses its own ports so parallel worktrees don't collide: the fleet binds port 0 (ephemeral; the real port is parsed from the "fleet listening" banner), vite gets a stable per-worktree port (`20000 + hash8 % 10000`, the same hash as the state dir; probe-picked fallback when taken) with `--strictPort`, so the origin and with it localStorage prefs, notification permission, bookmarks, and the open tab's HMR reload survive restarts; a pre-ready exit is retried on a fresh port (bounded), and vite learns the fleet port via the `OMP_DEV_FLEET_PORT` env in `apps/web/vite.config.ts` (the proxy always targets the fleet edge). Open the runner's `ui` URL: the fleet's own `/` serves `dist/` (stale or absent in a checkout). The runner folds the fleet's and vite's startup banners into one summary block (ui, `--host` network URLs, fleet, broker, state + restored sessions), dropping the originals (including the fleet's `Web UI:` line) so nothing prints twice. Auto-open passes vite `--open` on every interactive run (stdin+stdout TTY, no `--host`, a display on Linux); `--open`/`--no-open` override, `BROWSER=none` disables, and vite inherits stdin so its `o + enter` shortcut reopens. Fleet state is scoped per worktree too: `OMP_FLEET_STATE` → `<config dir>/dev-fleets/<slug>-<hash8>/fleet-state.json` (slug = worktree basename, hash8 = sha256 of the worktree realpath; deterministic, so dev restarts reuse the same fleet), which also scopes the pidfile lock (`<state>.lock`), so several worktrees' dev fleets and the user's real fleet on the shared data home run side by side; nothing is written into the repo. Only the state is scoped (the lock guards just that file), so the config file (read-only) and the managed-worktree root stay shared across all fleets, workspaces coordinate at path level (`.omp-web-repo` markers, existing-target refusal, git's no-double-checkout), and any fleet can discover/manage worktrees another fleet created; orphaned `dev-fleets/` dirs left by deleted worktrees are inert (safe to delete by hand once their dev stack is stopped; no auto-GC). Dev mode: `bun run dev` sets `OMP_FLEET_LOCAL_TEMPLATE` so sidebar-spawned daemons run `bun apps/session/index.ts` from the checkout (not `--watch`ed, restart to pick up server edits); `--host`/`--allow-hosts` bind vite to the network (backends stay loopback; see README for the tailscale host-check note).

## The wire contract (OMP_PROTO 2)

Transport is HTTP + SSE, no WebSockets on the agent-driving path:

- **Up**: `POST /command`, one `ClientCommand` per request, answered `202`; every command carries a client-supplied `id` (dedup window `COMMAND_DEDUP_WINDOW_MS` 60s; ids remembered up to `COMMAND_DEDUP_ID_CAP` 4096 as a flood backstop, recorded answers only up to `COMMAND_DEDUP_ANSWER_CAP` 64, since answers can be large). Answers ride the SSE stream as `call_result` frames.
- **Down**: `GET /events`, SSE, `event: frame`, `id: <seq>`, `data: <JSON ServerFrame>`. Priming (seqs 1..k): `hello_ok` → `attached` → `history` → `state` → `collab_status` → `available_commands` → `ready`; the fleet edge primes its browser streams itself (`roster` + merged `daemons` + `registered_projects`, plus `daemon_activity` for ready daemons) and proxies the attached daemon's priming down the per-browser pipe. Then daemon-global delta seqs ≥ `SSE_DELTA_SEQ_START` (1024) via a byte-bounded `SseRing` (8 MiB / 10k entries), resumable via `Last-Event-ID`. Past `SSE_BACKPRESSURE_BYTES` (4 MiB) the stream is terminated in-band with a `stream_reset` frame (drop-and-resume; the daemon is ALIVE; do not treat the clean close as dormant).
- **Identity**: `hello_ok` is the FIRST event on every stream open (`proto`, `name`, `cwd`, `pid`, `version`, `sessionFile`). omp-session prints `OMP_SESSION|{...}` JSON contract lines on **stdout** (`event: listening` with bind/port/url, or `endpoint`); **all logs go to stderr**.
- **Priming on a bare omp-session**: `connect = attached` (every `/events` stream is attached to the single live session from open). The fleet edge **stamps** `sessionId = daemonId` on session-scoped frames and sends `attached` and the `roster` frame itself when proxying, so clients can guard daemon switches; a bare session daemon never sends `roster`, so the client shows the fleet-required notice.

Key constants (all in `lib/wire/protocol.ts`): `OMP_PROTO = 2`, `SSE_KEEPALIVE_MS` 15s, `SSE_SILENCE_DEADLINE_MS` 30s, `SSE_RING_CAP` 10k, `SSE_RING_BYTES` 8 MiB, `SSE_DELTA_SEQ_START` 1024, `SSE_BACKPRESSURE_BYTES` 4 MiB.

## Invariants & conventions, read before editing

### Protocol (`lib/wire/`)
- **Additive-only.** Adding a `WebMethodName`, `ClientCommand` variant, or `ServerFrame` variant is fine; changing or removing shapes is a **breaking change** → bump `OMP_PROTO` and coordinate the fleet connector + edge proto gates (`connector.ts` hello gate, `edge.ts` pipe gate) with it.
- History over the backpressure cap ships as byte-bounded sequential `history` frames (`final: false` … `final: true`); small transcripts are one frame with no `final`. Client accumulates until `final`. Frames batch at 512 KiB (`HISTORY_CHUNK_BYTES`) but each message is only degraded above `MESSAGE_REPLICATION_CEILING_BYTES` (1 MiB): images stripped first, then progressive string/array clipping, so a 512 KiB–1 MiB message ships verbatim in a paced frame of its own.

### Server
- **stdout is reserved for `OMP_SESSION|` lines; logs to stderr.** Spawners parse stdout.
- POST `/command`: `202` accept; dedup re-accepts duplicates. `READ_ONLY` methods (12 rows in `methods.ts`) skip post-mutation broadcast; `HISTORY_RELOAD` methods (`newSession`/`switchSession`/`branch`/`fork`/`handoff`) resync chunked history **before** `call_result`. `NOT_READY_GATED` = prompt-family calls fail `not_ready` until the readiness gate clears.
- Auth (R14): loopback peers exempt; off-loopback requires bearer (`Authorization: Bearer` or `?token=`); wrong credential → 401. Binding a non-loopback host without `--token` is a **startup error**.
- Callback flags (fleet-managed sessions): `--callback-url`/`OMP_SESSION_CALLBACK_URL` requires the workspace-bound pair (`--callback-workspace`, `--callback-generation`); HTTPS is enforced at startup, and `--callback-allow-http`/`OMP_SESSION_CALLBACK_ALLOW_HTTP=1` opens HTTP only for loopback hosts. `--callback-proxy` must be http/https; never silently ignored. See `docs/clone-contracts.md` "Callback transport".
- `/download` is realpath-jailed to cwd + tmpdir + session-file dirs, the only file-egress path. `list_files` never escapes cwd.
- Idle auto-exit (default `--idle-timeout 30m`): no attached clients, no running agent/queue, no in-flight bash/eval, no open dialog, no live collab room. `0` disables. The `.jsonl` is durable; fleet marks the entry `asleep` and respawns with `--resume`.
- One live session per process (`BOOT_HANDLE "s1"`). Mux commands (`create_session` etc.) are rejected as unknown; multiplexing lives in omp-fleet.

### Fleet
- **Zero SDK state, with two deliberate fleet persistence exceptions.** Fleet persists only roster metadata (endpoints, per-spawn bearer tokens, `lastSessionFile`, `sessionTitle`/`sessionEmpty` probed from the lastSessionFile JSONL title slot + messageless-ness, git branch/dirty counts) and re-derives everything else by dialing daemons. The exceptions: (1) the fleet-private `WorkspaceRecord` on clone entries (kind, source, `pinnedRevision`, profile, desired state, generation, provider handle, deletion state; never serialized to roster/debug surfaces) and (2) the fleet log store (`logs/<workspaceId>/<sessionId>/<relpath>` + `index.json`), a durable mirror of lineage logs every managed daemon streams over the callback pair. While at least one browser is attached, the fleet edge retains a connector stream to each ready daemon, derives `{streaming, blocked}` per daemon from the tapped `state`/`ui_request`/`ui_request_end` frames, and broadcasts those as additive fleet-scoped `daemon_activity` frames (never persisted, never carry tokens/endpoints); a retained stream counts as an attached client, so a ready daemon's idle auto-exit is suspended while any browser is connected and resumes after the last browser disconnects (connector idle-drop), a deliberate, user-approved deviation from the old "never invent a fleet-side frame / idle-drop" invariant. The sidebar's activity dot derives `blocked`/`in progress` from the attached session's client state (attached row) or the edge's `daemon_activity` frames (detached rows; `remote` undefined when the edge predates the feature or a daemon's stream is down → idle); the yellow unreviewed dot is attached-only and view-gated (set when a turn ends while the transcript is scrolled away, cleared on re-pin / new turn / session switch; `chatPinned`/`answerUnviewed` in `apps/web/state.ts`), the light-blue unread dot is marked when a detached daemon's streaming flips true→false (the `daemon_activity` frame) or the user switches away mid-stream and cleared on attach (the switch-away mark is the fallback for old edges/fleets that never send `daemon_activity`; `apps/web/fleet-ui/unread.ts`). Git dirtiness NEVER folds into the dot (uncommitted changes are the row's diffstat chips, a separate display).
- **Per-worktree session dropdown.** Clicking a roster row opens a dropdown of the worktree's last-10 sessions (newest-first) instead of attaching directly; picking one resumes it. Listing rides a new fleet-edge command `list_daemon_sessions` → unicast `daemon_sessions` (`apps/fleet/daemon-sessions.ts` lists from disk via the SDK's `SessionManager` with a LAZY import; the fleet stays SDK-free at static load, omp-check precedent; agent dir resolves from the fleet's env, matching production spawns). Resume: `spawn_resume` carries an optional `sessionFile` (edge validates membership against that worktree's listing before `--resume <file>`, never an arbitrary path) for asleep rows; ready rows attach then `switchSession`. A row whose last session file is missing or messageless renders a "New session" title (`sessionEmpty` probe).
- **Exclusive state locks.** Fleet state and session files are pidfile-locked for the owning process's lifetime, self-healing via pid liveness: a second fleet (or a second daemon resuming the same session file) refuses to start instead of clobbering state. Both exit 77: a session-lock exit is `OMP_SESSION_EXIT_SESSION_LOCKED` (`lib/wire/protocol.ts`), which the supervisor never restarts; it returns the entry to `asleep` and rejects the waiting attaches (`connector.fail`) with the daemon's last stderr line, so the browser shows why at once instead of timing out.
- **Tokens are minted fresh per spawn/restart and must NEVER be serialized** into roster frames or `/ctl/debug` (tests enforce this: `apps/fleet/test/edge-wire.test.ts` asserts `toRosterEntry` output). Same for endpoints in `/ctl/debug` snapshots.
- **Unicast answers go to the origin browser only.** Each attached browser has its own daemon pipe, and the daemon broadcasts an id-keyed answer (`call_result`, `daemon_logs_result`, `daemon_control_result`) to every pipe, so the edge records the origin of each forwarded `call`/`daemon_logs`/`daemon_stop`/`daemon_restart` id (`#forwardOrigins`, cap 256, swept past `COMMAND_DEDUP_WINDOW_MS`, first forward wins while undelivered) and routes the answer to that browser's stream, consuming the other pipes' copies. An origin with no live stream keeps the record outstanding, so its re-POST's replayed answer still lands. Each record captures three proofs of the daemon PROCESS: the pipe's `hello_ok.pid` (`#daemonGenerations`), the endpoint it was POSTed to, and the bearer token it was sent with (fresh-random per spawn, so it is the earliest proof: it rotates before the new child dials). A replay whose id disagrees on any axis is answered by id with a refusal naming that axis (`daemon restarted before this command was answered (pid 42 → 77 | new endpoint | rotated credentials); re-issue it`), because the dedup memory that makes a replay safe dies with the process. Same-process redials still forward (the daemon answers or dedups). Cap eviction drops DELIVERED records only: forgetting an outstanding id would make its replay look like a first forward, which is exactly the re-execution the guard prevents (the TTL sweep still bounds the map).
- `dN` ids are monotonic and never reused. Registry persists atomically (tmp+rename) on every mutation.
- `pN` project ids are monotonic and never reused; projects are realpath-keyed and deduped on registration (a duplicate realpath returns the existing project). Registering a project auto-registers its **default workspace** (`registerProjectMainEntry` in `apps/fleet/worktrees.ts`): a roster entry for the main checkout mapped to the repo CWD (NEVER a managed worktree under `workspaceDir`), asleep and wakeable via `spawn_resume` unless `start` spawns it live. `removeProject` implicitly drops provably-empty placeholder entries (the never-started default workspace: spawned/asleep, no `lastSessionFile`, no endpoint) and refuses while any real roster entry references it, naming the blockers. Projects persist in the same atomic state file as the roster, and the `registered_projects` frame must NEVER serialize tokens/endpoints (same rule as roster frames; `apps/fleet/test/edge-wire.test.ts` enforces it).
- Managed worktrees live under the `workspaceDir` knob (flag `--workspace-dir` > env `OMP_FLEET_WORKSPACE_DIR` > config-file `workspaceDir` key > `~/.omp-web/workspaces`; the root is created lazily on first worktree, never at boot). Deleting one requires ownership (realpath under `workspaceDir`) AND a clean tree: no `--force` in v1; the optional branch delete is `git branch -d` only, never `-D`. Session transcripts live under the agent dir, never inside the worktree, so worktree deletion never touches them. Clone workspaces are separate: they are managed by the single lifecycle owner (`apps/fleet/workspace-lifecycle.ts`; see its own rules) through the `providerProfiles` config, and their deletion runs the verified gate (quiesce → Git guard → store verification → read-only flip → provider deletion → roster removal), never the git-worktree guards, which reason about a fleet-local cwd a clone volume does not have.
- Status ladder is monotonic `connecting < session < resolving < ready`; `error` is terminal (only respawn refreshes). `hello_ok` gates: `OMP_PROTO` mismatch → terminal error; registered cwd vs `hello_ok.cwd` mismatch → `error cwd mismatch` (empty registered cwd → adopt hello's).
- **Clone workspace lifecycle** (`apps/fleet/workspace-lifecycle.ts`) is the single create/ensure/stop/delete authority for provider-managed clones; HTTP handlers and edge commands call it, and nothing self-fetches `/ctl/*`. Desired state/generation/handle/source/pin/progress persist before retry-prone provider steps; predecessor termination is proven (never PID-only; `conflict` blocks replacement) before a generation bump; destructive transitions run the verify-at-deletion gate (admission → quiesce with proven stop → Git guard → fleet-store verification cross-checked against the workspace volume's own session tree → read-only flip → provider deletion → volume deletion → roster removal). Stop preserves checkout + session logs; only the gate deletes. No force override on the Git guard (dirty/untracked/stash/unpreserved-history block; transcripts are not source backup). Retention is explicit and manual: deleted-without-verification store subtrees are orphans (`GET /ctl/logs/orphans`), removed only by `POST /ctl/logs/purge`; verified read-only stores are never GC'd. Wake (confirmed): a stopped clone wakes onto its last session via `OMP_SESSION_RESUME`; cold/missing transcripts materialize byte-identical from the store over the bulk channel before the `--resume` path; an explicit session pick on a ready clone switches to the real session (never a fresh boot) and a nonexistent explicit id answers typed `unavailable` without waking compute. Before a wake resume the fleet unlinks the stale `<session>.lock` beside the target (bwrap pid namespaces confuse the daemon's liveness probe; safe because stop proof precedes the generation bump). Deleted workspaces resume only via the explicit `POST /ctl/workspaces/:id/resume-clone` (typed `unavailable` on missing source/pin/transcripts, on an unwired `CloneResumeSpawner`, never a fake spawn; no upstream substitution).
- `providerProfiles` (config key; validated in `apps/fleet/provider-profile.ts`): malformed entries drop with an actionable warning and the fleet still boots. bwrap secretRefs use `env:NAME` (values in the provider process env; sandbox never mounts operator agent state); k8s secretRefs use `<secretName>/<key>` → `secretKeyRef` pod env. Public profile view (`toPublicProfile`) is secret-free and is what roster frames and `/ctl/profiles` serve.
- Endpoint resolution order (spawn): last `{event:"endpoint"}` wrapper line › template `host` + listening port › `advertise` › loopback. 30s endpoint timeout → error + kill.
- Spawn templates: `{cwd}` `{token}` `{name}` `{labels}` `{resume}` substitution, `sh -c`, no shell escaping in `fillTemplate` (caller `shellQuote`s). `OMP_FLEET_LOCAL_TEMPLATE` replaces the `local` template command outright (dev runners). `DEFAULT_LOCAL_TEMPLATE` is `omp-web session --cwd {cwd} …`; installed-mode spawns hit the single entrypoint; dev overrides via env.
- Config default is `~/.omp-web/config.json` (`resolveConfigPath`: explicit path > `OMP_FLEET_CONFIG` > default). The file is read-only-loaded and shallow-merged (unknown keys tolerated, legacy configs keep loading); **`writeConfigFile` (`apps/fleet/cli.ts`, the serve first-run offer) is the only writer**. `fleetFacts.configPath` is null when no file exists; that + empty roster = first-run. The default **state path lives next to the config** (`<config dir>/fleet-state.json`, `resolveStatePath`; explicit/`OMP_FLEET_STATE` win) so the first-run data-home choice moves config + state + workspaces together. Bare `omp-web` = fleet serve (`apps/cli/omp-web.ts` injects `serve` for an empty argv); the TTY-only first-run offer (no config + stdin TTY) runs the omp-stack check (`apps/fleet/omp-check.ts`, SDK probe via LAZY import so the fleet stays SDK-free: omp binary on PATH/`~/.bun/bin`, auth-usable providers via `getApiKeyForProvider`, default-role model from `settings.modelRoles.default`), prints status + the omp-standard config advice when missing, then ONE prompt (`Data home directory [~/.omp-web]: `, Enter = default, alternate path with `~/` expansion overrides, `n` declines) writes the config. The offer is TTY-only (non-interactive spawners that parse the banner never reach it), so its status lines, prompts, and confirmations print to **stdout** normally; only errors go to stderr.
- `GET /ctl/fs/browse?path=` (edge route; `apps/fleet/fs-browse.ts`): directory picker backend, `~`/`~/` expanded server-side, realpath-canonicalized, subdirectories only, name-sorted, 500 cap, dot-dirs skipped in listings only, 400 on missing/not-a-dir/unreadable. Projects enter the fleet ONLY by explicit registration: no root scanning, no `roots` config key.
- Spawns that arrive with just a cwd (`/ctl/spawn`, the edge `spawn` command, sidebar "start a session" action) are stamped with the owning registered project's `projectId` via `projectIdForCwd` (`apps/fleet/worktrees.ts`: main-checkout realpath match, else linked-worktree match) so the roster groups them under the project; unregistered paths stay untagged (fallback group).
- Remote/add entries are dial-in only; never probed with local git (branch/dirty counts are local-cwd-only). Managed clone daemons are the exception: they have no inbound service and dial the fleet's callback pair outbound with workspace enrollment credentials (`x-omp-*` headers + bearer; HTTPS except the explicit loopback-HTTP dev exception). The callback pair and the log store are the clone-transport contracts in `docs/clone-contracts.md`.

### Frontend (`apps/web/`)
- **One `createStore` in `apps/web/state.ts` is the entire client model.** Components read `state` reactively and mutate only through exported actions. Don't introduce per-component state for shared data, and don't add a state library.
- **Markdown is ALWAYS `DOMPurify.sanitize(marked.parse(...))`** (`apps/web/text/markdown.ts`): model output is untrusted raw HTML.
- Streaming: deltas buffer in `pendingDeltas`, flushed ≤60/s via `requestAnimationFrame`; **mutate live blocks in place** (`setState('live','blocks',i,'text',…)`), replacing block objects remounts `<For>` and kills the fade/scroll behavior.
- Stale-frame guards (in the `/events` onmessage handler, `apps/web/state.ts`): drop session-scoped frames whose `sessionId !== currentSessionId` (`attach_result` exempt); dedup ring-replay via `seenFrameSeqs` per prime window; every attach/session-switch resets `nextId = 1` and rejects in-flight calls. `daemonRoster`/`daemons` survive session resets (fleet-scoped, not session-scoped).
- `state.fleetRequired` is the fleet-required gate (module-level `rosterSeen`, reset per connect): set when an `attached` or `hello_ok` frame arrives before any `roster` frame on this connection, and the `roster` frame clears the doubt. App renders only `FleetRequiredNotice` (root class `fleet-required`) instead of the shell while true.
- An unanswered `call()` recovers itself (`apps/web/store/transport.ts`): the SAME command id is re-POSTed every 5s until the answer arrives or `COMMAND_DEDUP_WINDOW_MS` has passed since the first POST. The daemon never re-dispatches a deduped id, it replays the recorded answer, so a replay can neither execute twice nor report a different outcome, and a lost `call_result` (dropped pipe, backpressure reset, lost accept) no longer hangs until the caller's deadline. `call(..., 0)` disables only the deadline, not the replay. A replay whose id belonged to a daemon process that has since restarted is refused by the edge (an error answer, never a silent re-execution), so the recovery is at-most-once across a respawn.
- The `registered_projects` frame carries `configPath` (string | null, additive; older edges omit it → client treats missing as null); `state.fleetConfigPath` is fleet-scoped like `daemonRoster`. First-run gate: `fleetConfigPath === null && registeredProjects.length === 0 && daemons.size === 0` → the roster's FirstRunPanel (welcome + add-project CTA + "just run `omp-web`" hint). Project groups show a hover "start a session" button (G4) that calls `spawnDaemon(project.path)` while no main-checkout daemon row exists (`worktreeOf === undefined`).
- Solid gotchas: use `untrack` when reading reactive objects inside effects you don't want to re-run (roster broadcasts replace daemon entries); `<Show when={…} keyed>` for object-identity-keyed rendering; `createRenderEffect` for imperative canvas (CharacterAvatar); module-level state survives row remounts where component signals don't (e.g. `activatingIds` in DaemonSidebar).
- localStorage keys: `omp.sidebarVisible`, `omp.notifyEnabled`, `omp.sidebarUsage`, `omp.sidebarGroupsCollapsed`, `omp.view`, `omp.txSidebarVisible`, `omp-web:theme`, `omp-web:font-size`, `omp-web:history`.
- Module layout: logic/data modules live in feature dirs, `apps/web/sprites/` (pixel-art sprite engine + character data), `apps/web/prompt/` (slash commands, autocomplete, prompt history, danger-confirm), `apps/web/text/` (markdown, diff, clipboard, images), `apps/web/usage/` (context thresholds, usage rows, model-options), `apps/web/fleet-ui/` (dir-picker browse model, daemon uptime + fleet-debug parsing), `apps/web/prefs/` (client theme + settings-panel display helpers), `apps/web/chat/` (tool-run grouping). `apps/web/store/` holds the per-domain action modules behind the `state.ts` facade; `apps/web/components/` is presentational only.
- Usage data is a one-shot mirror, never polled: `refreshUsageReports()` (`apps/web/store/usage.ts`) single-flights the READ_ONLY `fetchUsageReports` relay into `state.usageReports/usageLoading/usageError`; both the UsageModal and the roster-sidebar widget (`SidebarUsage`, gated by `omp.sidebarUsage`) read that mirror. The SDK caches provider /usage ~5 min (±jitter) upstream, so extra refresh clicks are cheap but timers are prohibited here.
- Styling: one global stylesheet split by domain, `apps/web/styles/` holds `tokens.css` (design tokens + `:root[data-theme=…]` palettes), `base.css` (reset, `.icon`, global button/focus, pointer:coarse hit-targets, badge geometry), `app.css` (shell + status bar), `chat.css` (stream/markdown), `tools.css` (tool/bash renderers), `prompt.css` (composer/autocomplete), `modals.css` (dialogs/pickers/ask), `settings.css`, `fleet.css` (sidebar/roster/projects/debug), `usage.css` (meters/breakdown), plus `apps/web/tx/tx.css` co-located with the transcripts view. `apps/web/styles.css` is the `@import` entry; import order encodes the original cascade and is load-bearing: new files/rules go in a position that preserves it. Plain kebab-case feature-prefixed classes (`msg-*`, `tool-*`, `bash-*`, `settings-*`, `daemon-*`…), design tokens as CSS custom properties in `:root` (`--space-1..7`, `--r-*`, `--fs-*`, `--z-*`), theme palettes override only `--*` vars. No CSS modules, no inline styles except rare one-offs.
- Dev handle: `window.__ompState` (DEV only). No router; modals keyed off `state.modal === …`.

### Style
- Tabs for indentation (enforced by oxfmt). `verbatimModuleSyntax` is on → `import type` discipline (no value imports of types).
- Imports into shared libraries use extensionless `#lib/<path below lib/>` (for example, `#lib/wire/protocol`), including parent-directory imports between libraries. Keep ordinary local relative imports such as `./helpers`. Root `package.json` owns the single `"#lib/*": "./lib/*.ts"` mapping; do not duplicate it in TypeScript or Vite aliases. Libraries are closed: every resolved repository import from `lib/` stays inside `lib/`, with no library cycles.
- **Git identity comes ONLY from the user's `.gitconfig`.** NEVER set an identity yourself: no `git config user.name`/`user.email` writes (local or global), no `-c user.name=…`/`-c user.email=…` on commands, no `--author=`/`--committer=` overrides. - Typecheck with `tsgo` (`bun run check:types`); the `@typescript/native-preview` version is pinned exactly. NOTE: typescript-eslint/ESLint cannot run against TS 7. That's why linting is oxlint, not ESLint.
- **SDK pins**: the seven `@oh-my-pi/*` packages repo code imports (`pi-agent-core`, `pi-ai`, `pi-catalog`, `pi-coding-agent`, `pi-tui`, `pi-utils`, `pi-wire`) are pinned exactly (18.7.0) and declared without a patch: this repo ships no patch file, and a fresh install carries no root `patchedDependencies` entry for `pi-agent-core`. - Comments reference audit remediation findings as `finding #N` (numbering kept from the 2026-08 audit); keep the numbering when fixing/annotating.
- `dist/`, `node_modules/` are gitignored; `docs/architecture.md`, `docs/release.md` are committed docs: update, don't delete.
- Docs and markdown prose use no em dashes (AI tell): use periods or commas instead, never en-dash or hyphen stand-ins. En dashes inside numeric ranges (12–18px) are fine.

## Editing workflows

**Add a web-exposed method**: 1) add to `WebMethodName` in `lib/wire/protocol.ts`; 2) row in `METHODS` (`apps/session/methods.ts`), classify `READ_ONLY` / `NOT_READY_GATED` / `HISTORY_RELOAD`; 3) handler in `apps/session/index.ts` (post-mutation broadcast unless READ_ONLY; resync-before-`call_result` for HISTORY_RELOAD); 4) `call()` from `apps/web/state.ts` + UI; 5) tests.

**Add an SSE frame**: 1) variant in `SessionScopedFrame` or `ServerFrame` (additive); 2) emit site in `apps/session/sse-delivery.ts` broadcast path; 3) client handling in `apps/web/state.ts` (apply stale-frame guards if session-scoped); 4) tests.

**Breaking handshake/frame change**: bump `OMP_PROTO` in `lib/wire/protocol.ts` AND update the proto gates in `apps/fleet/connector.ts` (hello) and `apps/fleet/edge.ts` (pipe) so old/new peers fail loudly instead of misparsing.

**Bug fix**: reproduce first (heavy suites give you the seams: hermetic fake daemons in `apps/fleet/test/`, `FakeEventSource` in `apps/web/test/state.test.ts`), then fix, then confirm the reproduction no longer triggers. Don't suppress warnings/errors to make tests green: the suite uses `--retry 0` and `--timeout 15000`; flaky-by-design is not acceptable.

## Verification

After any change: run the **targeted test file(s)** (`bun scripts/test.ts <file>`), then `bun run check:types`, then the full `bun run test` when the change touches library/daemon/edge paths. UI changes: `bun run dev`, the only UI dev loop (vite HMR :4713 proxied to the fleet edge), and verify in a browser against the actual surface; a page pointed at a bare session daemon must show the fleet-required notice. Readiness is observable: the daemon's `OMP_SESSION|` line, vite's `Local:` line, fleet's control API answering `/ctl/sessions`. Distribution/onboarding changes (`apps/cli/`, the bundle, first-run config): `bun e2e/onboarding.ts`, the offline pack → sandboxed global install → config → bare serve → spawn → update round-trip gate.

A release runs more than a contributor check: the gate is `GATE_COMMANDS` in `scripts/release.ts` (`bun run check:types`, `bun run format:check`, `bun run build:web`, `bun run test`, `bun e2e/onboarding.ts`), followed by build/pack and the packed-tarball install smoke (`smokePackedTarball`: the packed tarball is installed into a temp sandbox whose `HOME` and `BUN_INSTALL` point inside it, and the installed `omp-web --version` must print the release version). `bun scripts/preflight.ts` reports release drift before a run; it is advisory, and the orchestrator never calls it.
