## Unreleased

omp-web reconciles the single-session browser UX: equivalent browser capability through existing SDK/fleet/transport reuse. Wire is OMP_PROTO 3: a mismatched web, fleet, and session refuse each other.

### Features
- Projects sidebar: projects are the top level and every checkout of a project is a row under it. The fleet detects worktrees itself (`git worktree list`, including ones made in a terminal, detached and locked ones) and keeps them in sync; a project whose main checkout disappears is marked missing. Rows show a kind icon (main checkout, worktree, clone), the branch, the last session title, and git stats. The empty state points at the Projects "+" and offers provider sign-in when none is configured; the first-run panel, the "Other" group, and "Add remote session…" are gone. The session process log opens at the newest line with live refresh, copy, and an "errors only" filter.
- Add project: a folder chooser (path bar, Home and recent repos, Git badges) that opens next to the last project you added. Picking a linked worktree or a subfolder adds its main checkout; adding a project never starts a session, and template and labels are CLI-only (`add-repo`).
- New workspace: the "+" on a project opens one popover to create a worktree from a new or existing local branch (branches already checked out are greyed), or, when provider profiles exist, a clone on a profile from a local or remote source (remote branches via `git ls-remote`; Kubernetes clones use a remote source, defaulting to the project's `origin`). A typed name keeps `/` in the branch name (`feat/Login fix` creates branch `feat/login-fix` in folder `feat-login-fix`), and Enter in the search field only creates the typed branch; an existing branch is picked explicitly. Replaces the Add workspace dialog.
- Remove project stops and drops all of its rows (transcripts kept, nothing on disk touched); clone workspaces still block it.
- Delete worktree: "also delete branch" is decided from git (merged, nothing unpushed); the default/base branch and the main checkout's branch are never deleted, and the command names the branch so a branch switched since the confirmation is kept.
- Fleet: git probes no longer take `index.lock` (`--no-optional-locks`), time out, and never overlap; asleep rows are probed every 60s. A vanished worktree that never ran a session is dropped without a toast. Creating and starting a worktree from the web reuses the row the sync registered for it instead of adding a second one; `omp-web spawn` still adds a session to a folder that already has one.
- CLI: `omp-web projects` lists registered projects (id, name, path, worktree count) instead of unregistered worktrees; `rm-worktree --delete-branch <name>` takes the branch name; `add-worktree --existing` is removed (worktrees are detected automatically).
- BTW: `/btw` opens one sheet holding the side question, its answer, the saved history (search, thread, copy), and Promote to transcript; `/btw-history` is removed. Side questions are saved as they run, so promote works for them.
- Lifecycle: same-session clear, new identity, provider-state fresh, and session-ID-confirmed durable delete with fleet purge acknowledgment; misleading `/drop` alias removed (`/delete` + menu action replace it).
- Settings: effective value, owning layer, explicit presence, unset eligibility, SDK warnings, and live/next-session/restart effects on every row; typed record/list editing; project layer read-only with config-file guidance.
- Session graph: searchable ID-anchored tree with same-file navigate vs new-file branch, ask re-answer transaction, and entry-ID branch-from-card (no text-equality lookup).
- Analysis: the session browser searches prompt and conversation text as well as title, folder, cwd, and id, and shows each session's first prompt; the transcript header's Open in Chat resumes through the validated resume path; a stored session that fails to load shows a readable message (Retry only when retrying can help) instead of a raw `ApiError`; the transcript list drops `@tanstack/solid-virtual` for `content-visibility`. Body search covers on-disk sessions only; fleet-stored rows match title, cwd, and id.
- Subagents: subagent tree rows (kebab) and the agent pane header offer "Open in Analysis" when Analysis is enabled and the parent session file is known; it opens the subagent transcript at `#/s/<parent>?sub=<subagent>`. Hidden otherwise.
- Editor: partitioned drafts, large-paste folding, and file attach validation. The composer's vim toggle and export/copy/import draft buttons are removed.
- Queue: queued steers, follow-ups, and slash commands keep their pasted images and text files. Chips show file names and an image count (for example "2 images"); Edit and Alt+↑ restore the images and text files to the composer. Each queued image is limited to 10 MB after decoding; an oversized one is refused with an error.
- Models: temporary session-only switch with effort-clamp feedback, preset list/save/apply/delete, and branch-local model-worker chips.
- Review: daemon-bound Git stage/unstage/hunk/commit with fingerprint gates; versioned plan approval with stale refusal; durable anchored annotations with drift/orphan marking; canonical phased todos with revision conflicts.
- Workers: searchable hub with live focus/steer, park/revive/resume lifecycle, advisor config/status/transcript, and guided goals/loops plus Vibe director controls.
- Integrations: real skills/commands reload with consent; MCP/skill rows report explicit unavailable until headless extraction lands; declarative browser extension UI with terminal-only incompatibility diagnostics.
- Portability: explicit compaction modes with eligibility, durable BTW history with guarded promotion, manifest-backed downloads through the fleet origin, SessionScope-bound voice control rows over the existing SSE stream, and targeted resume/pins/foreign import.
- View modes: Work mode is renamed Chat mode (switcher button, labels, and store state); a persisted `work` view boots into Chat.
- Tool cards: edit, write, apply_patch, patch, and hashline cards show a `+n −m` summary that expands to a unified diff (side-by-side when wide) instead of raw JSON or numbered text. Ctrl+O toggles all tool cards from anywhere, including the composer; the four-state pill group is replaced by an expand-all toggle in the header menu.
- Status bar: the Compact button beside the `ctx` meter is removed. The meter opens Session stats, which offers Compact now and Compact…; `/compaction` still opens the dialog directly.
- CLI: terse startup (one `omp-web listening on …` line, then warnings and errors only; `--verbose` restores paths and every lifecycle event), and `omp-web --help`. Bare `omp-web` and `omp-web ui` open the UI in a browser only when run from an interactive local terminal (stdin and stdout TTYs, no agent or CI marker such as `CLAUDECODE` or `OMPCODE`, a display on Linux); `--no-open` opts out. `bun run dev`, `bun run design`, and `bun run demo` follow the same rule, so agents running them under a PTY no longer open tabs; dev drops its forcing `--open`.
- CLI: split setup with `omp-web control` (control plane only, default port 4722) and `omp-web ui` (static UI plus a reverse proxy to the control plane, default port 4723, `--control-port` to target another control plane); both bind loopback only.
- CLI: `omp-web serve` is removed; bare `omp-web` runs control plane + UI.
- CLI: `omp-web relay --port <n>` runs the collab room relay as its own process (`--hostname`, `--max-guests`, `--max-rooms`). Sessions no longer host a relay: `collab.relayUrl` names the relay to publish through.
- Collab: `collab.autoStart` (`off`, `view`, `control`; default `off`) hosts each boot session through `collab.relayUrl`. With no `collab.relayUrl` it is refused, and the reason is logged and shown in the UI. `view` and `control` currently behave the same. `collab_start` accepts an explicit `relayUrl`; `collab.displayName` names the host.
- Removed: the in-session relay, its `/r/` route, and the host token gate. `OMP_SESSION_COLLAB_URL`, `OMP_SESSION_COLLAB_HOSTNAME`, and `OMP_SESSION_COLLAB_MAX_ROOMS` are gone; `OMP_SESSION_COLLAB_MAX_GUESTS` is display-only and must match the relay's `--max-guests`.
- Fleet: every session daemon dials out to the control plane over the callback pair, and the control plane never opens a connection into a session, so sessions work behind NAT, in sandboxes, and in pods with no inbound traffic. Ctrl+C on `omp-web` or `omp-web control` no longer stops sessions: they keep running and redial the next control plane with the same credential.
- Fleet: a session with no control plane for 10 minutes (`--control-grace`, `OMP_SESSION_CONTROL_GRACE`; `0` disables) shuts itself down gracefully; one whose credential the fleet rejects shuts down at once. Local sessions are not mirrored; their transcripts stay on the host.
- CLI: `omp-web add <name> <url> --token` is removed. Remote enrollment is removed too: `omp-web enroll`, `omp-web provision`, `POST /ctl/enroll`, `POST /ctl/provision`, and `OMP_FLEET_SPAWN_HOOK` are gone; off-host compute runs as provider clones.
- Fleet: spawned sessions run detached, so a terminal Ctrl+C never reaches them; their stdout and stderr go to `session-logs/<daemonId>.log` beside the state file (not rotated). The Debug panel shows each session's callback pair state instead of a connector column.
- Settings sheet: the TUI's 10 settings tabs plus Installed, Web UI, and Features in a vertical sidebar (icons, changed-count badges, section anchors), each tab showing every section stacked in the TUI's order under a numbered heading and lead. Search spans every tab. Rows use toggles, select pills, segmented controls, steppers, mono text fields, a numbered list editor, inline `Edit…` editors, a `Reset` link, a changed dot, and the SDK's warning callout; the layer select and debug footer are gone. Terminal-only settings never show, and SDK settings the TUI does not list sit in a per-tab Advanced group, keeping their gates.
- Settings: Installed lists plugins with `Configure` (enable toggle, features, settings; secrets show only as set or unset), persisted to `~/.omp/plugins/omp-plugins.lock.json` with or without an attached session (additive `listPlugins`, `getPluginConfig`, `setPluginEnabled`, `setPluginFeatures`, `setPluginSetting`, and fleet `/ctl/plugins/*`).
- Settings now change the web UI live: transcript display (thinking blocks, tool activity, token usage, turn time, cache-miss marker, compacted history, images, smooth streaming), read and MCP tool rendering, intent tracing, subagent pins, live preview, model badge and title icons, composer autocomplete, emoji, paste folding, magic keywords, spelling and next-message predictions (additive `predictWord`, `predictWordFeedback`, `predictNextMessage`), and completion, error, and ask notifications. Unnamed sessions are titled through the SDK's auto-title flow, so `title.generator` applies. The Web UI notification toggle is now only the browser permission grant, and the reveal-queue toggle is replaced by `display.smoothStreaming`.
- Theme: when the OS prefers light, the default theme is catppuccin-latte; the plain light theme stays selectable.
- Composer: Up with the caret on the prompt's first line opens a prompt history popover anchored at the prompt's top-left corner and growing up and to the right (newest prompt at the bottom, Up for older, Down past the newest back to the prompt, type to fuzzy-filter, Enter or click inserts). It replaces both inline Up/Down history cycling and the Ctrl+R history search dialog; Ctrl+R is no longer bound.
- Debug sheet: a Build section at the top shows the omp-web version and git commit the UI was built from, and the upstream omp version with the omp.sh logo.
- Features: Analysis mode is off by default; enable it in Settings > Features. Only non-default choices were stored, so browsers that had it on now start without it until it is enabled again; a persisted Analysis view or `#/s/…` link falls back to Chat.
- Layout: the top status bar is gone; the app is a sidebar and a main pane. The sidebar header carries the `omp-web` wordmark (version on hover), the Chat/Analysis switch, the debug button, and a sidebar toggle; the main pane header carries the session title, goal, subagents, connection state, and the settings gear at top right. Compacting, auto-retry, and plan badges sit at the start of the session config bar by the composer. Errors show as a sticky error toast (dismiss or replace by the next error), docked top-right below the main header (full width on narrow screens).
- Responsive layout: below 1024px wide both sidebars are drawers that start closed and close when you pick a session or open a dialog; at 1024px and up they dock and remember their state. Below 768px the session config bar stays on one row (cost and tokens open from the context meter) and the transcript view toggles move into a header menu. On touch screens controls are at least 44px, text inputs use 16px (no iOS zoom), and a tap opens the thinking picker. Safe-area insets, an iOS keyboard-aware app height, short-viewport collapsing of the queue and background bars, stacked background bars, scrollable wide markdown tables, and a close button on every dialog, sheet, and lightbox round it out.
- Composer: the placeholder is just "Message the Agent"; the key hints (Enter send, Ctrl+Enter follow-up, / for commands) no longer crowd the input.
- Sidebar usage: each provider account is one block: the provider logo (Anthropic, OpenAI, OpenCode; other providers show their initial), the same size for every account and three bars tall, beside its stack of limit bars, with the time left in each window to the right of its bar. Limit labels, percentages, and reset times move to hover text; warning and exhausted limits tint their bar.
- Composer: the send controls sit on the input row as icon buttons (attach, a robot with the running-subagent count that opens the agents panel, Stop, Send or Steer), and the model, context, and cost bar moves under the input. The Discard button with its Recover banner and discarded-draft history entries, the touch-only history button, and "Stop, keep subagents" are removed; Stop always stops running subagents too.
- Brand: omp-web has its own logo, a warm wave crest under an amber sun. It is the browser favicon (follows the system light/dark scheme), the iOS home-screen icon, the mark beside the `omp-web` wordmark in the sidebar header (follows the app theme), and the docs site logo and favicon.

### Fixes
- Fleet: sessions no longer show `reconnecting` every 5 minutes. The session dropped and redialed its callback pair on a 5-minute timer that served no purpose (the credential does not rotate, and heartbeats already detect a dead pair), and the fleet flipped the row to `reconnecting` on every drop. The timer is gone; the pair renews only after 64 MiB of upload (Bun's request-body cap). A pair that drops for a moment (that renewal, or a network blip) now stays `ready` in the roster and shows `reconnecting` only if it is still down after `PAIR_LOSS_GRACE_MS` (5 s); attaches and prompts wait for it to redial instead of respawning it.
- Usage: the sidebar usage panel and the Usage reports dialog (Session stats → usage reports) load on page load. They read provider usage from the fleet (`GET /ctl/usage`, from the agent dir's auth storage) instead of the session `fetchUsageReports` RPC, which failed before the event stream opened ("Failed to load usage") and needed an attached session. A failed fetch answers a fixed message; the provider error goes to the fleet log.
- Sessions: the fleet no longer hands a session its callback pair or listener token through environment variables or argv. A spawned session gets both in one JSON payload on stdin (`--fleet-stdin`), so no command its agent runs can inherit them, and `ps` no longer shows the listener token. Before, an `omp-session` started from inside a session (for example by running the session tests) connected to the fleet as that workspace, took over its browser attachment ("Stale session attachment"), and overwrote its saved session file. Spawn templates use `{fleet}` instead of `--token {token}`, and a template containing `{token}` is refused at load. The `--callback-*` flags and the `OMP_SESSION_CALLBACK_*` and `OMP_SESSION_TOKEN` variables are removed; `--token` remains for manual launches. bwrap clones receive the same payload on stdin; Kubernetes pods keep the values in pod env, and the entrypoint moves them into the payload and unsets them before starting the session.
- Sessions: `--resume` restores the requested transcript or exits 78 with the reason, and the fleet parks the row asleep without restarting it. This covers a transcript that exists but cannot be restored (for example, recorded under another project directory) and one that was written and later deleted. A session that never had messages relaunches as the same empty session (`--resume-unwritten`); the fleet tracks which session files the session has reported written (`sessionPersisted` on the state frame).
- Tests: `bun run test` and `bun run test:isolated` strip inherited `OMP_SESSION_*` variables. Run from a shell inside an omp-web session, the daemons tests spawned inherited that session's callback pair, dialed the live fleet as it, received the browser's commands (failing the dedup and resume tests), and overwrote the session's roster `lastSessionFile` with a test temp transcript.
- Sessions: an SDK-generated session title (first message or replan) is broadcast to the main pane when the SDK sets it; it previously reached the sidebar row first (fleet file probe) and the main pane only on the next state resync. The SDK name listener is the one state broadcast for a name change: `setSessionName` and `resumeRename` skip their post-call resync, and the slash runtime's `notifyTitleChanged` no longer broadcasts (its callers also rename or call `notifyConfigChanged`).
- Sessions: a call the edge refused as `not attached` while a session re-attaches is retried once with the same command ID inside the dedup window, instead of failing. Subagent progress goes out at most once per second per agent as deltas, with `lastTool` replacing the bulk `recentTools` and `recentOutput` fields (additive wire change). A dropped session shows a connection strip under the main header and disables session actions with a tooltip, instead of stacking error toasts, and the sticky error no longer reads `Error: Error:`.
- Vite: explicit extensions in config imports eliminate native-config compatibility warnings during `bun dev`.
- Sessions: a browser attached through the callback pair gets the transcript again, on attach and after New session, switch, branch, and every other transcript-replacing call (the pair primed and resynced without `history` frames, so the old transcript stayed on screen and re-attaching showed it empty). History frames are paced against the pair's outbound buffer and bounded to fit one callback envelope.
- Models: the model picker no longer fails with `call "getAvailableModels" timed out` on large catalogs. The answer now carries only the picker's fields (provider, id, context window, reasoning, thinking) instead of full SDK model rows, which ran past 2 MiB and over the callback pair's 1 MiB envelope cap, so it was never delivered.
- Transcript: `!`/`$` shell and python runs render from history as settled cards (command, output, exit code, dimmed for `!!`/`$$`), so they survive reloads, re-attaches, and session switches instead of vanishing.
- Subagents: the worker hub lists live subagents again (it filtered by the SDK session uuid instead of the attached handle, so it opened empty while the status bar counted them); rows and the focused worker header show the spawned subagent name beside its agent type, in-flight glyphs spin, and progress updates key on the subagent id so equal indexes from separate task calls no longer merge and status/task changes re-render.
- Subagent hub layout: the filter toolbar and Goals/Advisor control rows no longer reserve 260px of height each (the steer-cluster flex basis now applies only inside a worker row); underlined tabs, a single-line wrapping toolbar, a wider dialog, and rows that truncate the description and model instead of overflowing.
- Worker detail view: no longer wipes and refetches the transcript on every subagent frame (the scope-reset effect tracked an unmemoized key over a per-frame `sub` object), which made the view flicker between the transcript and "loading…"; its header wraps instead of squeezing the back button.
- Subagent lists (task card, active strip, worker hub) render rows keyed by subagent id instead of per-frame objects, so rows no longer remount on every progress frame: spinners rotate smoothly, clicks on a row open its detail view, and the hub keeps a stable order (in-flight first) instead of reshuffling by last update.
- Advisor notes render inline in the conversation (they were dropped as unhandled custom messages): one card per delivery, live and from history, matching the TUI advisor card with note count and blocker tally, per-note severity rail and badge, advisor attribution, `T-n` age, and the first three notes shown until expanded (Ctrl+O or the card's own toggle).
- Opening a session renders its history without a long main-thread stall: the transcript replay built the chat with one store write per message, each copying the list and re-walking every earlier item (~420ms blocked on a 2 MB transcript); it now commits once (~80ms).
- Picking a session from an asleep row's dropdown resumes that session again: the attach sent alongside the wake no longer races ahead of the pick's validation and wakes the daemon on its last session instead.
- The empty-session character no longer flashes the fallback robot (or the previous session's character) when attaching or starting a new session: the transcript primes before the session's state frame, so the greeting now waits for that state to land before drawing the model's character.
- Removed the fleet-required notice: the browser no longer replaces the whole shell when its `/events` peer sends `attached`/`hello_ok` before a `roster` frame. The session daemon still serves no web UI.
- Settings: Reset works with no session attached (`/ctl/settings/unset` had no route), fleet writes honor `expectedRevision` with 409 on a stale revision, and an older `settings_changed` frame no longer replaces a newer model. The settings model loads at boot and on attach, and the rejected project-layer write option is gone; project values show as read-only.
- Settings: a session settings write asks for its revision with the trailing `"revision"` reply option, so the reply is a small `{ revision }` ack instead of a second copy of the full model; the model arrives once on `settings_changed`, and the browser refetches only if that push is behind the ack. Clients that omit the option keep the full-model reply.
- Sessions: a session process you stopped stays stopped across reloads in this browser (the sidebar keeps Stopped with Restart), and opening its route no longer wakes it. Restart clears the mark.
- Fleet: a command whose session process connection drops after it was sent now reports "the change may have been applied, refresh to check" instead of "not attached", so a retried change is not mistaken for a failed one.
- Copy: user-facing "daemon" text is now "session process" across the fleet dialogs, onboarding, the loop panel, downloads, and command messages.
- Review: Stage all and Commit confirm in a dialog with Cancel focused, replacing the browser confirm; Stage all is disabled when nothing is unstaged.
- Errors: failures in chat, roster, queue, review, and settings report through the shared error path, so they show as the same toast everywhere.


### Fixes
- Slash/`@` autocomplete: the popup renders every match (it rendered only the first twelve, so the mouse wheel could not reach later commands, and arrowing past row twelve appended rows without scrolling, hiding the selection); keyboard moves scroll the selection into view, and pointer selection follows mouse movement only, so wheel-scrolling rows under a still pointer no longer changes the selection.
- `/resume` dialog: one titled header instead of "History" plus a "Resume from disk" label, fixed-width one-line rows whose titles truncate before a right-aligned `N msgs · 2h ago` column, a `current` marker on the attached session, and the always-identical project cwd and full timestamp moved to the row tooltip (the filter now matches titles only).
- Git review, plan review, annotations, todos, and voice open in a closable sheet or dialog (they rendered bare, in page flow, with no Esc, backdrop, or close). Every summonable surface now has an opener: `/mcp`, `/skills`, and `/todo` open their dialogs when bare and forward arguments to the agent; `/git`, `/plan-review`, `/annotations`, `/voice`, `/compaction`, and `/btw` open theirs.
- Daemon details and the image lightbox are store-driven overlays mounted by `ModalHost`, so global shortcuts and session resets see them; the daemon details dialog closes when its daemon leaves the roster, and the lightbox reuses the shared `Modal` focus trap instead of a copy.
- Workspaces: deleting a worktree whose git state cannot be read is refused up front instead of proceeding on `git worktree remove` alone; the confirm dialog shows the reason and offers only Cancel, and `worktree_delete_info` carries the additive `probeFailed` flag.
- Clone deletion treats an unverifiable transcript tree as a refusal, not as empty: an unreadable volume session tree (or a volume root that cannot be read) reports the typed archive conflict and keeps the checkout, volume, and store; export planning no longer drops depth-2 artifact directories depending on directory order (subagent, advisor, and metadata bytes were missing from flush evidence and the delete gate), and materialize planning no longer follows symlinks.
- Sessions: `/ctl/stored/*` answers the documented typed error envelope (`{error:{code,message}}`), so clients read an error `code` again instead of a bare string.
- Sessions: a callback down-stream resume whose `Last-Event-ID` is past the retained ring is refused with 400 `invalid_request` instead of silently restarting the sequence space under a deduping consumer.
- Fleet: a session whose up half goes silent past the silence deadline tears down its down half, so a dead daemon stops reporting paired (a roster "ready") and commands fail fast instead of writing into a zombie socket.
- CLI: `omp-web update` fails loudly when the installed version differs from the manifest's; it previously accepted any non-empty version string.
- Locks: releasing a file lock that another process broke as stale and re-acquired no longer deletes that holder's lock (each lock records its owner token, and release checks it).
- Release tooling: the LLM changelog turn drains `omp` stdout before reading its exit status, so a real turn can no longer come back empty.
- Ask tool: the `ask` card no longer fails with `undefined is not an object (evaluating 'theme.status')`. The daemon runs the pinned SDK in-process with no terminal, so nothing initialized the SDK's terminal theme singleton, which the pinned ask tool reads while shaping its dialog before it opens one. The daemon now initializes it and suppresses terminal notifications (which wrote OSC bytes into the stdout channel reserved for `OMP_SESSION|` lines) at boot, in `apps/session/sdk-tui-globals.ts`.
- Ask tool: with that crash gone, the dialog still failed with `No connected client to answer the UI request`. The daemon's presence check counted only its own `/events` consumers, while every production browser rides the callback pair as a virtual stream, so `askDialog` (and extension browser contributions) found no client to answer; the check and the pending-dialog bookkeeping now count callback-pair browsers too, while the pair is live: a dialog opened during an outage fails fast instead of waiting for a frame the mirror drops.
