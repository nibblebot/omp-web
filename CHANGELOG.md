## Unreleased

omp-web reconciles the single-session browser UX: equivalent browser capability through existing SDK/fleet/transport reuse. Wire is OMP_PROTO 6: a mismatched web, fleet, and session refuse each other.

### Breaking changes
- OMP_PROTO 6 (`3a8h`): the fleet-managed session process is now a "session" and its id a `workspaceId` everywhere; "daemon" now only means a supervised background process. A tab on proto 5 is closed with 4426, and a running proto-5 session is refused at `hello_ok` until it is restarted. Wire renames: `attach` and `attach_result` carry `workspaceId` (was `sessionId`, which now means only the conversation), the edge's per-frame attachment stamp on session-scoped frames and the `attached` frame carry `scope` (was `sessionId`: the roster workspace id through the fleet, a standalone session's opaque boot handle on `attached`), so the stamp never shares a key with the `workspaceId` that fleet frames and commands use to name a roster row, `daemon_status` is `session_status`, `daemon_activity` is `session_activity`, `daemon_sessions` is `workspace_sessions`, `list_daemon_sessions` is `list_workspace_sessions`, `roster.daemons` is `roster.entries` (`DaemonEntry` is `RosterEntry`), every other `daemonId` field (`spawn_resume`, `stop`, `remove`, `delete_worktree`, the worktree and workspace-create results) is `workspaceId`, and the `stream_reset` reason `daemon_resync` is `session_resync`; the never-produced `"session"` and `"resolving"` status literals are gone (the sidebar's waking spinner is a web-only `waking` row signal). The `/ctl` control API JSON uses `workspaceId` for every former `daemonId` field (URL paths are unchanged apart from the param name). The fleet registry still loads a `fleet-state.json` written with `daemonId` and rewrites it with `workspaceId` on the next save. That migration is one-way: after the first save the file has no `daemonId`, so a downgrade needs the `fleet-state.json` from before the upgrade (the previous release's parser refuses the new file with `entry missing daemonId`). Provider-managed clones write `session.log` (rotated like before) and readers fall back to `daemon.log` for clones created before the rename. The browser route is `#/w/<id>` (was `#/d/<id>`; old `#/d/` links no longer resolve). The CLI and its messages say `<workspace-id>` and "unknown session".
- OMP_PROTO 5 (`vyyq`): every client connection is one WebSocket on `GET /ws` (`lib/wire/browser-socket.ts`), replacing `GET /events` (SSE) and `POST /command`. The browser, `omp-web ui`, the profile harness and a direct client of a standalone session all speak it. Frames arrive as `{"seq":N,"frame":…}` messages, commands go up as `{"cmd":…}` and are acked or nacked with the status `POST /command` used to return, a dropped socket resumes from `after=<last seq>` out of the same per-client replay ring, and a command that was not acked is re-sent with the same id after the reconnect.
- A reverse proxy or ingress in front of the control plane or `omp-web ui` must now pass the WebSocket upgrade on `/ws` (HTTP/1.1 upstream, `Upgrade` and `Connection` headers, `Cookie`, `Origin` and `X-Forwarded-For` forwarded, messages up to about 32 MiB, no buffering of upstream messages) and idle for more than 30 s (keepalive every 15 s, the page reconnects after 30 s of silence). The docs site's "Reverse proxies and ingress" page has the nginx and ingress-nginx settings.
- A direct client of a standalone `omp-web session` dials `/ws` instead of `/events` and `/command`, and passes its token as the `token` query parameter or an `Authorization: Bearer` header (a browser cannot set the header on a WebSocket). The session listener now also refuses cross-site loopback dials: a foreign `Host`, `Origin` or `Sec-Fetch-Site` is closed 4403, as the fleet already did.
- Refusals at dial time are an upgrade followed by an immediate typed close (4401 sign-in, 4403 forbidden, 4426 protocol mismatch), because a browser cannot read a non-101 status. A socket that stops draining is closed 4503 and resumes; log-out and session expiry close the session's sockets 4401. With browser auth on, the origin check on the upgrade replaces the per-command CSRF token for commands.
- `omp-web ui` bridges `/ws` beside `/callback/ws`, pauses the upstream while more than 1 MiB sits unsent to the browser, passes the control plane's typed closes through, and closes 4503 when the control plane is unreachable.
- Workspace labels are removed, within unreleased OMP_PROTO 5 with no version bump. Gone: the CLI `omp-web spawn --label` and `omp-web add-repo --labels` flags, the `labels` column of the `omp-web sessions` table, the `labels` field of `POST /ctl/spawn`, `POST /ctl/projects` and the browser `spawn` command (an old client that still sends it has the field ignored), the `labels` field on roster entries, the `label:k=v` and `tag:k=v` selectors (such a selector is now an ordinary name glob), and the label chips in the sidebar and the Process details dialog. The `{labels}` spawn-template placeholder is removed too: delete it from a custom template in `config.json` or `OMP_FLEET_LOCAL_TEMPLATE`, where it would now be passed through as the literal text `{labels}`. A `labels` key in an existing fleet state file is dropped on load and is gone after the next write. Reload open browser tabs after upgrading between pre-release builds.
- `omp-web add-repo` is renamed `omp-web add-project`, with no alias, because a project no longer has to be a git repository (`kxnj`).
- Bun 1.4.4 or newer is required (the SDK's engine floor since 18.13.3); the installer refuses an older Bun.

### Android and installable web app (`017t`)
- Installable web app (`dfja`): a web app manifest (standalone, start URL `/`), 192, 512 and maskable icons, and a `theme-color` that follows the active theme. A notification-only service worker (no fetch handler, no offline cache) shows session alerts on Android Chrome, where `new Notification()` is unavailable; tapping one opens or focuses the app on that session. Links in rendered messages open in a new tab, so following one never leaves the installed app. The fleet serves the shell, manifest and worker `Cache-Control: no-cache` and hashed assets for a year, and the connection strip offers Reload when the page is older than the server. Install needs a secure context: docs site, "Install as an app".
- Composer on soft keyboards (`tdvh`): Appearance > Composer has an Enter key setting (Auto, Send, Newline). Auto sends with a mouse and inserts a newline on touch, where the Send button sends; Shift+Enter is always a newline and Ctrl/Cmd+Enter always sends. Key handlers ignore IME composition. Touch gets buttons for prompt history, Take photo and Queue as follow-up and a tappable suggestion chip; oversize photos are downscaled instead of rejected. Below 480px wide the composer is one row: a one-line text box that grows with its content beside Send, with no history or photo buttons. While a turn runs there it shows Stop alone until something is typed, then Stop and Steer; holding Steer queues the message as a follow-up instead of steering. Attach files and the Subagents, Jobs, Daemons and Todo items move into the header's More actions menu, which shows a dot while work runs; an activity item opens its popover under the menu button. The activity bar then shows only while there is progress text. Send and Stop keep the keyboard open, pickers no longer pop the keyboard on open, the autocomplete popup stays inside the visible area, and the session and activity bars fold away while the keyboard is up. Drafts are saved when the page is hidden.
- Back gesture (`4wgm`): Android Back (and browser Back) closes the topmost popover, dialog, sheet, lightbox or sidebar drawer before it changes session, and closing the dock from its own button no longer leaves a history entry that Back reopens.
- Resume and relaunch (`snmj`): the socket redials at once when the page becomes visible again or the network comes back, and replaces a socket that went silent while frozen. Opening the app with no route attaches the last workspace if it is running, without waking an asleep one or switching its session.
- Layout and touch (`0q4z`): pull-to-refresh no longer reloads the app. Touch sizing (44px targets) applies to any coarse pointer, so landscape phones and tablets get it too, and hover-only styles apply only where hover exists. Below 1024px the dock covers the window like the sidebar drawer, and a reload on a narrow screen lands on the chat. A Command palette button in the header; "N hidden lines" is a button; compact settings show their descriptions on touch; title-only labels show on tap; folders open with one tap in Add project; ordered lists get Up and Down buttons. A user message's branch and copy actions are icon buttons (a fork and a clipboard) at every width; on touch they stay hidden until a long press on the message, float over its top-right corner without moving the text, and hide again on a press elsewhere. A touch fling re-pins the transcript, the jump-to-bottom arrow stays up the whole time the view is away from the bottom, the sidebar no longer overflows the drawer, kebab menus flip upward near the bottom, and on phones the header drops the breadcrumb and folds the Command palette, Appearance and Settings buttons into one More actions menu, so the session title gets the room.
- Readability (`qt4n`): the text size setting is relative to the browser's default size, so Android text scaling applies; its range is now 16 to 24 (stored smaller values read as 16). Long words wrap in user messages and notices, and code, diffs and terminal output wrap on phones. Muted, secondary and status text in the built-in themes meets 4.5:1 contrast (Everforest, Gruvbox, Tokyo Night, Kanagawa, Rosé Pine, Nord, Poimandres and Dark Volcanic colors adjusted), derived `muted-2` and `muted-3` are solved to 4.5:1, and the theme checker reports them; dimmed rows use the muted color instead of opacity.

### Completion estimates (`9xmx`)
- Subagents show their self-estimated completion, like the omp TUI: a completion ring, percent and stage on tree rows, the Activities popover, the subagent status bar and running task rows of the wait card. omp-session runs the SDK's own completion probe (`task.completionProbe`, as in the TUI: only subagents the main agent spawned, first estimate after 2 min, then 5, 10, 30 min and hourly, 99% once the agent has yielded its report) and adds the estimate to `subagent_progress`, `getSubagents` and `workerList`. It does so without marking the process an interactive host, so the SQLite busy timeout stays 1 s and subagents get no replan title refresh. Each probe's cost is logged on the subagent's session usage but not added to its row's cost.

### Plain-directory projects (`kxnj`)
- Add project accepts any directory. A folder inside a git repo still registers the repo's main checkout; a folder with no git repo above it registers as itself. The Add project dialog no longer warns about or blocks non-git folders.
- A plain-directory project shows only its rows' session titles and actions: no branch, diffstat, worktrees, clones or New workspace "+". `add-worktree`, branch listing and clone creation refuse it with "project is not a git repository". The fleet detects `.git` appearing or disappearing in the project directory and switches the project to or from a git project; registered projects carry `git: false` on the `registered_projects` frame (additive, never persisted). When a project loses its `.git`, its linked worktree rows are removed from the sidebar (transcripts kept), a running one once it stops.
- Worktree discovery is watcher-driven: a worktree added in a terminal appears within about a second, with a 60 s poll fallback where the filesystem gives no events. Asleep rows are no longer re-probed: their branch, stats and title stay as last seen (stats muted) until the session wakes.
- Sidebar project headers show an open or closed folder icon instead of a chevron. Every row now shows a title: "New session" when the workspace has no session or an empty one, "Untitled session" when it has messages but no title yet.

### Frontend performance (`90nc`)
Fixes from the frontend performance audit (`90nc`, items FP01-FP28). Wire changes are additive under OMP_PROTO 6 and OMP_CALLBACK_PROTO 2; a session started before the upgrade keeps working. Before/after measurements: `scripts/profile/results/2026-10-28-frontend-perf-audit.md`.

#### Memory
- A live transcript no longer keeps every earlier copy of its item list: memory now grows linearly with session length instead of quadratically (`ykq0`).
- The browser-socket replay dedup set is a fixed window instead of one entry per frame (`mtwr`). Capped tool output no longer pins the full original string. The bash chunk buffer is capped while the tab is hidden. Raster image thumbnails (PNG, JPEG, GIF, WebP, AVIF, BMP) are `blob:` URLs from a cache bounded by decoded bytes instead of 200 data URLs; any other image type, including SVG, stays a `data:` URL, so a tool image can never open as a same-origin document (`macn`). A reverse proxy that sets a `Content-Security-Policy` with `img-src` must allow `blob:`.
- Subagent transcripts are kept only while a pane shows them, plus the three most recently closed, and are dropped on a session switch (`188s`). A closed dialog or sheet is no longer kept alive by focus restore (`427z`).

#### Transcript
- A long transcript opens at its last 30 items and mounts the older ones in idle-time chunks of about 16 ms of work each, so switching to or reopening a long session no longer blocks the page for the whole transcript and no chunk is a long task (`c891`). Every item is mounted once the backfill finishes (about a second for a 300-turn session, longer on a slow CPU), so the browser's find-in-page and free scrolling work as before from then on; a jump to a tool card or a scroll near the top mounts what it needs at once. Items pushed to a live session stay mounted.
- The stream stops following the bottom only on reader intent: wheel or touch scroll up, scroll keys, dragging the scrollbar, or a jump to a card. Layout shifts no longer unpin it, so a find-in-page match while the reply streams is scrolled away by the next content growth.
- Per-item transcript metadata (tool runs, wait runs, turn info, Activities-hidden cards) is indexed by item id, so adding an item or a live tool, bash or wait frame no longer rescans the whole transcript (`dj7t`).
- Streaming: finished segments of the live reply are isolated from the growing tail; big tables and lists re-parse only their unfrozen tail; message end reuses the per-block HTML (`pwzk`). The /btw side answer streams the same way.
- Markdown is sanitized once per render, and rendered HTML is cached by source text, so a remount does not re-run marked and DOMPurify. The syntax highlighter starts loading after first paint, so a first attach no longer renders every code block twice (`c1qb`).
- Closed tool-card bodies, collapsed JSON nodes, thinking blocks and the compaction summary mount on first open. Eval tables show 100 rows with a "more rows" button, and diff cards stop at the row cap until Ctrl+O, like the other tool cards (`41gw`).
- Fix: a live message with a tool call before later text no longer stops updating until the message ends (`rqyn`).

#### Network and reconnect
- A dropped browser socket resumes from the fleet's replay ring: the reconnect `attach` carries `resume: true`, and when the ring still covers the client and the session pair is unchanged, the edge answers `attach_result {resumed: true}` with no history re-prime, so the transcript stays mounted. The edge keeps a dropped tab's session channel for 60 s (paused on the session with the new `stream_pause`/`stream_resume` controls) and releases it at once on a normal close; the web client's own redial closes 4408. A `history` frame for the session already on screen keeps the unchanged item prefix (`7qyy`).
- The fleet serves hashed `/assets/*` as immutable, `index.html` with `no-cache` and an ETag (a reload revalidates with 304), build-time `.br`/`.gz` files by `Accept-Encoding`, and gzips `/ctl` JSON answers over 1 KiB; `omp-web ui` passes them through (`jxky`). The shipped dist grows by the precompressed files.
- Boot: the page dials `/ws` and renders before the feature chunks load (a static boot shell paints first), default-on feature chunks are preloaded, and a reload into a session attaches the workspace named in the URL without listing its sessions first (`h5bk`). Dialogs and sheets load lazily, Git Review reaches the dock only through a feature slot, and the QR encoder moved into the Share sheet's chunk (`4nw7`).
- An attach reads only the settings values the app needs at boot (`getSettings({ paths })`, `GET /ctl/settings?paths=`); the full settings model loads when the Settings or Appearance sheet or the palette first needs it (`0mzh`). The Settings sheet mounts the tabs near the viewport and search results in pages (`jttt`).
- The Ctrl+K palette, the `/resume` picker and the session tree search once per typing pause (200 ms) instead of per keystroke, and the palette's stored-session search starts at two characters. `files` and `sessions` answers carry the command id, so a late answer to an older query no longer replaces a newer one; an answer without an id from an older session settles the latest request as before (`h8b9`).
- `sendCommand` encodes each command once (`rw47`). The Session stats dialog asks for brief tool schemas (`getToolSchemas({ brief: true })`); the usage dialog reuses data refreshed in the last minute and keeps it on screen while refreshing; downloads fold chunks into a Blob every 4 MiB and update progress at most every 100 ms (`s2a3`). Drafts with attachments rewrite only the part that changed (`rw47`).

#### Rendering and idle cost
- The working-label shimmer and skeleton lines animate `transform` only, the sidebar usage ring ticks every 5 s without a transition, and every infinite animation holds still under reduced motion; lint now fails on an infinite animation outside `prefers-reduced-motion: no-preference` (`9x73`).
- Clocks, polls and auto-refresh (sidebar usage, session log, debug sheet, row and subagent clocks) stop while the tab is hidden and catch up on return. Popovers track their anchor with observers instead of a per-frame loop. The retry badge counts down (`6j04`). Dragging the dock resizes the pane once per frame and saves on release (`r7wv`). Roster frames index rows by id, and settled sidebar rows use `content-visibility` (`k9q4`).
- Subagents: one shared forest per progress change instead of one per consumer, an in-place subagent map, one shared elapsed ticker, and a paced single-flight worker roster refresh (`pxfv`).
- Analysis (in development): the hidden view no longer polls or syncs stats during chat, rows keep their DOM across page loads, find is debounced over cached search text, and the session list is windowed; the stored raw view asks the fleet for at most 256 KiB (`?maxBytes=`) (`5tft`). Git Review (in development): selection is a set, file lists are windowed, and file diffs no longer carry unused full file text (`2yac`); the staged and commit diff views show their patch again (`m4jy`).

### Fixes
- A bwrap clone starts when `bun` is installed under the operator's home (the default `~/.bun/bin/bun`). The sandbox masks the home directory and bound only system roots and the runtime package, so the runtime binary was missing inside it (`execvp ... No such file or directory`). The runtime binary is now bound read-only as a single file when no other mount covers it; one inside the ssh directory, fleet or provider state, or an agent or container socket is refused (`qr30`).
- Collab: a long streamed answer no longer ends the room for every guest with "collab send backlog exceeded its limit" (only the latest state of a streaming message is queued); guest frames that arrive after the session switched are refused and end the room once; a relay room recreate drops stale peer ids, so they lose write access.
- Extension input dialogs that ask for a secret (`ctx.ui.input(..., { secret: true })`) render a masked field and are never offered to collab guests, whose answer path would carry the value in plain text.
- The ask card names the option a note is on ("Note on X").
- BTW: a follow-up on a topic saved by the terminal UI with images sends those images again, as the TUI does, and BTW lists no longer carry image payloads to the browser.
- Approving a plan from the review panel keeps tools that extensions registered after plan mode started.
- Renaming a non-attached session from the resume list holds its lease through the write, so a session another process opens meanwhile is refused instead of forked.
- A session whose configured default model is unavailable shows a warning naming the fallback model.
- Web search cards show a fallback provider's note as text instead of listing URLs from its failure reasons as results; task cards label a task-file call by its file; a job glance shows `140/190` instead of a bare `140` beside its meter.
- The HTML export consent says the file loads its viewer from the network.
- Settings: the SDK's new Prewalk from/into, Restricted Folders, xd:// mount notices and Task file rows show in their tabs, rate-limit chain walking is under Advanced, and terminal-only rows (advisor collapsed lines, resume worktree scope, print wake, extension assistant-text renderers, extension mode control, `out://` replies) stay hidden.
- `/skill:<name>` from the composer runs the skill: the session expands it into the skill prompt, as the terminal does, with attached images, instead of sending the literal command text to the model. Unknown skills, or skill commands turned off, still go through as plain text.
- A fleet without browser auth answers the page's `GET /auth/session` probe with 200 `{ "enabled": false }` instead of 404, so loading the UI no longer logs a failed request in the browser console (`0pam`).
- Below 1024px, hovering the chat area while the sidebar drawer is open keeps the dimming scrim translucent; the button hover color painted it opaque over the whole chat.
- Advisor: the advisor card in the transcript no longer has an "Open advisor" button; the Advisor sheet (status, enable or disable, transcript) opens from the Ctrl+K palette's Advisor entry.

### Infra remediation (kfg5)
Fleet, session, and wire fixes from the infra audit (`kfg5`). Wire is OMP_PROTO 4. OMP_PROTO 4 removes uncalled session methods and state fields as well as adding frames (see the protocol note in `lib/wire/protocol.ts`). A fleet behind a trusted proxy requires the proxy to append the client to `X-Forwarded-For`; see "Trusted proxies" on the docs site's "Running omp-web" page.

#### Security
- Behind a trusted proxy the fleet resolves the client from `X-Forwarded-For` right to left, skipping trusted hops, so a client-supplied `X-Forwarded-For: 127.0.0.1` no longer earns the loopback auth exemption (`ebmq`).
- Loopback requests with a foreign `Host`, `Origin`, or `Sec-Fetch-Site: cross-site` are refused (the UI proxy applies the same check), and JSON routes require `Content-Type: application/json` (415 otherwise), so a web page or DNS-rebinding site can no longer drive a local fleet (`09cm`). `bun run dev --host` keeps working through the Vite proxy, and `omp-web ui` honours `--browser-origin`; a reverse proxy must set the browser origin on both processes.
- Pre-auth `/auth/*` bodies are capped at 4 KiB with a 10 s idle timeout, and repeated failed logins back off per client (429). `OMP_FLEET_TRUSTED_PROXY` applies without a config file (flag over env over file), a bare `--trusted-proxy` is an error, and missing static assets answer 404 instead of a 200 placeholder (`mpa5`).

#### Stability and resiliency
- "Stale session attachment; refresh before retrying" no longer greets a send right after New session. The SDK mints the new session id partway through `newSession` (and `switchSession`, `branch`, `fork`, `handoff`, `clearSession`, `deleteSession`) and the session only publishes it after the rest of the call, so a send in that gap carried the old session's scope. The composer now holds Send, with a "starting new session…" badge, until the call's answer (which follows the history and state resync) lands, and the session refuses prompt-family calls during a change with "Session change in progress" instead of running them on the session being replaced (`h900`).
- Finished and parked subagents stay readable after their session process restarts: a subagent's transcript loaded nothing ("Unknown subagent or session file unavailable"), and rows showed the agent id as its type with no title. Transcript reads now resolve every worker the roster lists, inside the same session-directory jail, and type, title and assignment come back from the parent's stored task results (`bax2`). Finished agents keep their final tokens, cost and elapsed time instead of an early 0-token sample.
- A subagent's transcript in the Activities panel shows its real images (screenshots, display output) instead of broken or missing ones: a new read-only `getSubagentImage` call fetches each persisted image by hash, only for hashes that transcript references, and an image too large for one callback envelope stays an `[image]` placeholder (`40dg`). Transcript pages are 256 KiB, so every page answer fits the 1 MiB callback envelope.
- A browser command larger than the callback envelope (for example a prompt with a pasted screenshot) no longer tears down the session's callback pair: the fleet forwards it in chunks that the session reassembles. Commands over 32 MiB are refused by name before sending and again at the fleet edge, and an oversize or malformed envelope fails only its own call (`3tvg`).
- Start on a Kubernetes clone resumes its last session like a bwrap clone: the fleet hands the pod the session file the runtime last reported (an in-pod path on the volume), or the stored main file of an explicitly picked session, as `OMP_SESSION_RESUME`, and a runtime restart after a pair-up resumes it too. A first start boots fresh, an explicit id that is neither reported nor stored is refused as `unavailable`, and a session file that is missing on the volume exits 78 instead of booting fresh (a clone wake's `OMP_SESSION_RESUME` is now strict like `--resume`; a file not known to be written carries `OMP_SESSION_RESUME_UNWRITTEN=1` and is adopted). The pod entrypoint clears a leftover session pidfile lock beside the resume target (`xvkk`).
- Browser-stream replay rings in the session release evicted frames and compact their backing array, so a long-lived session no longer grows its heap per frame (`xj47`).
- Browser streams re-prime after the callback pair is replaced, so frames emitted during an outage are no longer lost; orphaned browser streams are dropped after a short grace window instead of blocking idle exit; a down-only fleet leg no longer counts as paired and is torn down if no up half joins within the silence deadline (`d2s8`).
- Session process: a stop before the first fleet pairing exits gracefully instead of crashing with an unhandled rejection; shutdown has a 20 s hard deadline and a bounded callback drain; bulk materialize and upload transfers time out after 60 s and abort on stop (`axq2`).
- Supervision: an adopted session that exits after a fleet restart no longer stays `reconnecting` forever; the restart budget refills only after a stable paired window, so a session that crashes after pairing stops restarting; failed restarts and exit handling mark the row errored instead of stalling; the fleet never starts a second process while an adopted session still holds its lock; session redial backoff keeps growing when a fleet accepts and then drops each connection (`78rp`).
- Resuming a session older than your 10 most recent now resumes that session; a pick that cannot be resumed fails the attach with an error instead of starting a different session (`r5v2`).
- Failed and aborted bulk downloads release their capture slot and buffered data at once instead of hanging for 10 minutes; download payloads stream instead of being double-buffered, and more than two concurrent captures answer 503. Staged exports are bounded and cleaned up on success, failure, abort and shutdown, and the BTW download toggle now includes BTW history (`16q6`).
- Clone deletion gate: git calls are killed at their deadline instead of hanging when a child holds the output pipes, logs under a symlinked root verify correctly, and each session file is hashed in one streamed async pass (`yed6`).
- Clone start, stop, reconcile and delete admission for one workspace run one at a time, so concurrent starts no longer race on generation or enrollment. Wake transcript materialization writes atomically, re-fills truncated copies, streams the hash, and resumes reads from the cursor (`bpmm`).
- A provider-managed clone whose runtime dies after its callback pair came up (or after the fleet reattached it) now restarts: the fleet revokes the old credential, proves the predecessor gone through the provider, and starts a new generation with a fresh credential, using the same jittered 1s to 30s backoff as local sessions and 5-restart budget (refilled by a pair that holds for a minute). Past the budget the row shows `error`/`failed` with the reason. A brief pair drop while the runtime is alive, and an explicit stop, never restart it (`zn0e`).
- One crash policy for every runtime: a host session and a provider clone restart the same way (the dead generation's credential revoked first, jittered 1s to 30s backoff, a fresh credential and generation with the predecessor proven gone, a cap between pair-ups refilled by a pair that holds for a minute), and a spent cap shows `error` plus lifecycle stage `failed` with the reason for every kind (a host row used to show only `error`). An explicit start gives a host session a fresh cap, as it already did for a clone. A failed row of any kind retries in place from the Retry button. Provider ok responses gain optional `exitCode` and a bounded `detail` (at most 512 bytes) describing how a non-running runtime ended: the kubernetes provider reads the terminated container (exit code, reason, last log line from the kubelet's termination message) and bwrap reads its supervisor's exit record. The failed reason now carries that detail instead of only "sandbox stopped before the callback pair established", and a provider-reported exit 77 or 78 never restarts a clone: it goes `asleep` with the reason, like a host child (`0331`).
- Main-checkout and worktree sessions now run through the workspace lifecycle's `host` runtime, the same owner as clones, behind one internal runtime-provider contract (ensure-running, inspect, stop, delete; bwrap and kubernetes stay executables, the host runtime is in-process). Behavior is unchanged: fresh credential and generation per start, stdin-only payload, exit 77/78 and clean exit go `asleep` without a restart, crashes restart with the shared backoff and budget, `--resume <lastSessionFile>`, a restart refused while the old process holds the session lock, boot reconciliation, and sessions outliving the control plane. The spawn supervisor is gone; git-state polling and project sync live in `project-sync.ts`. `/ctl/debug` reports a session's runtime state under `host` instead of `supervisor`, and a launch that cannot start (log directory, `spawn` failure) now errors the row with `spawn failed: ...` in every path (`x7bd`).
- Start, stop and delete go through one set of lifecycle verbs for every workspace kind: the browser edge, the control API, the session waker (and so wake-on-click and prompts) and the worktree eviction call `start`, `stop` and `delete` on the workspace lifecycle, which picks the clone provider or the host runtime itself. `POST /ctl/start` (and `omp-web start`) now starts a main-checkout or worktree session too; it used to refuse anything but a clone. A host session whose stop fails is flipped to `asleep` by the lifecycle itself. The unused clone-control start/stop/remove helpers and the per-verb clone/host branches in the call sites are removed (`z96x`).
- A worktree delete that git refuses (locked or dirty) no longer drops the row: the session stops, the guarded removal runs, and the row is forgotten only on success. Browser and REST removals share one eviction path that also forgets the pair and marks store orphans (`xm8e`).
- Session dispatch: `shake` and image drops resync every open tab, `/compact` goes through its eligibility checks, malformed commands and inherited method names are rejected at `/command` (400), login code prompts work from fleet browsers, MCP add/update/remove reconnects only the changed server, and autonomy goal/loop state follows session switches and aborts (`hrc8`).
- Fleet state writes are coalesced, fsynced (file and directory), and backed up to `fleet-state.json.bak`, which the fleet loads automatically when `fleet-state.json` is corrupt; roster updates go to browsers as row-level `roster_delta` frames instead of a full roster per change. A failed state write now surfaces at shutdown or in the log rather than at the mutating call (`fp2p`).
- Session process logs are capped: each launch rotates a log over 1 MiB to `.log.1`, removing a session deletes its logs, and provider clones write stdout/stderr to a rotating `session.log` instead of keeping only a 4 KiB tail. The session log tailer rescans every 15 s while its watcher is healthy instead of every second (`78yx`).
- Fleet config that fails to parse is no longer silently replaced with defaults: an explicitly named config fails startup naming the file, and the default config logs the error and shows it in `/ctl/debug`. Failed SDK settings and provider lookups are retried instead of cached forever (`sg1g`).
- Wake materialization always ends a transfer with its terminal record, and a session rejects a transfer stream that ends without one instead of committing it as complete (`kfg5`).
- Stopping a collab share waits for the goodbye to be sent before closing the relay socket, so guests see the stop at once instead of after the relay's orphan timeout (`kfg5`).
- `omp-web preflight <profile>` now runs the provider's own live checks. Providers answer a new additive `preflight` op (`OMP_PROVIDER_PROTO` stays 1) with `{ok:true, checks}`: the kubernetes provider reports `kubectl`, context, API reachability, namespace, RBAC, StorageClass, Secret, and image rows (an unreachable context now fails a `kube-api` row with a remediation and exits 1), and the bwrap provider reports the bwrap binary, user namespaces, runtime entry, tools, and denied-bind rows. The fleet keeps the executable, callback, durable-dir, and secretRefs rows and merges the provider's; a provider that rejects the op (an older executable) or fails to run produces a failing `provider-preflight` row, never success. The placeholder `k8s-*` rows are removed (`6g2x`).
- The callback pair between a session and the fleet is one WebSocket (`OMP_CALLBACK_PROTO` 2, `GET /callback/ws`) instead of an NDJSON upload plus an SSE downlink, so it no longer renews: the upload leg used to be renewed every 64 MiB (Bun's request-body cap), which left a few milliseconds where the fleet answered commands "not attached" and re-primed every attached browser (the whole history, 5 to 25 MiB each, plus a `stream_reset`). Identity and the credential stay in the upgrade request headers, a configured proxy is passed explicitly (the WebSocket client ignores proxy environment variables), a refusal arrives as close code 4000 + status with the ledger code as reason, and neither side relies on the socket to buffer or drop: senders stop at a 1 MiB high-water mark and keep the rest in their bounded queues. Bulk transfers stay on `POST /callback/bulk/<id>` (`ddka`, `gv1m`).
- A reverse proxy or ingress in front of the control plane must now pass the WebSocket upgrade on `GET /callback/ws` (HTTP/1.1 upstream, `Upgrade` and `Connection` headers) and idle for more than 30 s (heartbeats every 15 s, silence deadline 30 s); the docs site's "Reverse proxies and ingress" page has nginx and ingress-nginx settings. With `OMP_FLEET_CALLBACK_URL` set, `omp-web preflight` adds a `callback-ws` row that attempts a real credential-less WebSocket upgrade to `<url>/callback/ws` (through the `HTTP(S)_PROXY` the session would use) and tells a refused or never-answered upgrade, a non-fleet endpoint and a reached fleet apart; the `callback-url` row skips the direct DNS and TCP check when a proxy applies (`8bvg`).
- Attaching to a very large history (20 MiB and up) no longer sends the whole history twice. A callback pair renewal that landed mid-prime restarted it from the top, with a second `attached` after a `stream_reset`; the pair no longer renews, so a prime finishes once (`g8nh`, the same cause as the pair fix above).
- Opening a session with a very large history no longer fails when the browser reads slower than the fleet writes: the browser stream used to be ended mid-priming (a clean end with no reset, repeated on every reconnect) once more than about 8 MiB had been sent ahead of a slow reader. The fleet now paces the session's priming and history resyncs by the browser's drain: a session holds at most 3 MiB of a burst unacknowledged per browser and the fleet acknowledges as the browser's queue drains (a `stream_ack` control). A browser that stops reading entirely is still dropped, now after 30 s without draining (checked on the 15 s keepalive sweep), so a stuck tab holds at most that window in the fleet and the session parks the rest (`0tas`).
- `omp-web ui` no longer replaces a session's callback pair, losing the frames in flight, when the session's kernel socket buffers deliver a 9 to 12 MB burst at once (a fast sender through the bridge). The pair now has an 8 MiB upload credit window (inside `OMP_CALLBACK_PROTO` 2): a session keeps at most 8 MiB sent beyond what the control plane has consumed, the control plane grants credit (`pair_credit`, every 512 KiB it consumed) only after it processed the bytes, and a socket that ignores the window is closed `invalid_request`. What the bridge or a reverse proxy can hold for one session is that window, not a guess about kernel buffers (`1vqd`, `vr40`).

#### Performance and efficiency
- Streaming replies send per-block deltas instead of the whole message on every update, so bandwidth for long replies grows linearly instead of quadratically; browsers that attach mid-reply still receive the in-progress message (`f7t3`). Collab guest frames keep the SDK's cumulative shape.
- A bash call that prints 40 KB no longer puts about 300 KB of frames on every browser stream: `tool_execution_update` carries only the appended output (the SDK repeats the whole output and the call's args in each update) and is not sent when nothing the card shows changed, tool-result `message_start`/`message_end` are not sent (`tool_execution_end` already carries the result), `turn_end` is a bare marker, and `agent_end` carries the last assistant message's outcome (`lastAssistant`) instead of every message and tool result of the turn. Browsers that attach mid-tool are primed with the output so far, and a history resync is followed by a full snapshot of each running tool's output. These reshapes are not additive but stay within the unreleased OMP_PROTO 4 by decision, with no bump: an OMP_PROTO 4 build from before this change passes the version check yet disagrees on these frames, so restart its sessions and reload browsers when upgrading between pre-release builds. Collab guest frames keep the SDK's shape (`ns60`).
- State frames no longer carry the system prompt or tool schemas (about 27 KB per frame); the usage dialog loads tool schemas on demand (`getToolSchemas`). Read-only RPCs no longer trigger state broadcasts, an idle turn end emits one state frame, and the daemons roster is sent only when it changes (30 s heartbeat) (`6ehp`).
- Fleet log ingest group-commits appends once per ack batch instead of fsyncing and renaming per chunk (about 7.1 ms to 0.27 ms per chunk in a local bench); acks are sent only after the commit succeeds. Base64 chunk payloads are validated by canonical decode with no size cap, and boot-time log-store repairs are logged as a warning (`kx3w`).
- Transcript caches in the fleet are bounded by bytes instead of entry count (a synthetic store dropped from 617 MB retained to about 214 MB), and the stats.db WAL fallback no longer re-copies the database on every probe (`ap7s`).
- Wire hot paths are cheaper: frames and callback envelopes are serialized once and shared across recipients (SSE fan-out to 50 browsers about 46x faster in a local bench), SSE parsing no longer rescans per chunk (up to 114x on 1 KB chunks) and cap an SSE line at 16 MiB, budgets count UTF-8 bytes, the edge's no-op virtual-stream queue is gone, and wake materialization streams files as the client pulls them (`ftwk`).
- Stored-session reads no longer walk and parse the whole store per request: one shared 64 KiB head parser replaces five copies, listings keep per-session summaries, and transcript paging reads only the requested window through a sparse line index (`k9e0`).
- Fleet git-state sync probes up to four rows at a time (one row's probes never overlap), skips the diff-stat run for clean repos, reads clone checkouts from `.checkout`, and fills session titles even when a repo probe fails (`j8wn`).
- Review, graph and collab paths do less work per call: duplicate collab hellos are rejected and join snapshots serialize once, advisor transcript renders are cached, annotation git probes are memoized and time out after 10 s, and review fingerprints use stat identity for untracked files (`v3ne`).
- The session serializes each frame once on its way to the fleet instead of about five times per delta with one browser attached (ring accounting, the envelope size check, and the envelope record were each a full stringify, per stream). The payload JSON and its byte length are shared by the control stream, every browser stream and the replay ring, and the envelope record is assembled around it, so the per-stream seq stamp no longer forces a re-stringify; replay re-sends the stored JSON. Wire bytes are unchanged (`OMP_CALLBACK_PROTO` stays 1). The control mirror also stops carrying streaming deltas no fleet consumer reads (`message_update` and `tool_execution_update` events, `bash_chunk`, `python_chunk`), which halves callback up-leg bytes and fleet NDJSON parses per text delta; browser streams still receive them, ringed and replayed as before. Fleet activity, `lastSessionFile`, the daemons roster and prompt fan-out read only `state`, `daemons`, `ui_request`/`ui_request_end`, `call_result`, `error` and `message_end`/`agent_end`/abort events (`1svw`).
- The fleet no longer re-serializes session frames on their way to browsers: it still parses every frame to decide what to do with it, but forwards the session's own JSON text (with the `scope` stamp spliced in) when the message arrived canonically framed and holds no line break, so priming a large history costs less CPU in the fleet. Other frames fall back to the previous path (`vr40`).

#### Wire and cleanup
- Removed the session's unused quiesce protocol (`quiesce_begin`/`quiesce_result` callback frames, writer barrier, evidence collection, and the verify-store manifest path); the clone delete gate already proves the stop and verifies the store against the volume (`5c65`).
- Callback pairs no longer emit acknowledgement envelopes or keep a fleet down-leg replay ring with Last-Event-ID resume (no client used them); a new fleet drops an older session's ack without tearing the pair down (`wqd2`).
- Fleet-managed sessions (started with `--fleet-stdin`) no longer bind a direct `/events`/`/command` listener or print the `OMP_SESSION|` listening line; standalone sessions keep it, with bearer auth via the `Authorization` header only. Removed the session `/download` route, `?token=` auth, `--advertise`/`OMP_SESSION_ADVERTISE`, session-side `--label`/`OMP_SESSION_LABELS` (fleet labels are unchanged), and the `endpoint` line; paced priming waits on stream drain instead of spinning (`57sn`).
- Removed about 1,100 lines of uncalled session RPC methods, the unreachable advisor config editor, the web's legacy unknown-method fallbacks, and the constant capability reports; the browser sees only the git capability, and session state no longer carries the steering, follow-up, interrupt, or image-inspection mode fields (`bsx1`).
- The fleet edge and the REST control API share one operation layer (`operations.ts`, table-driven edge command validation, one `SessionWaker`): both validate labels and clone sources the same way, stop and delete clones only through the verified lifecycle gate, and a prompt to a reconnecting row wakes it instead of timing out. REST error statuses for worktree, project and clone operations now match the edge (`jgc5`).
- Removed dead fleet, CLI, and settings modules (`btw-lineage.ts`, `runtime-resources.ts`, `collab-cli.ts`, `download-policy.ts`, the test-only settings path table), the unreachable resume-onto-fresh-clone and lineage-resume paths, and the uncalled `/ctl/auth/revoke-all` and `/ctl/auth/rotate-token` routes; token rotation remains a config change applied at boot (`63rn`).
- Provider runtimes (bwrap, kubernetes) share one callback-env reader, response helpers, and atomic record writer, and `ProviderProfile` is defined once in `lib/runtime/provider-protocol.ts`; the bwrap pidfile is written with mode 0600 (`x1z6`).
- The provider protocol no longer carries process identity: the pidfile record and `/proc` reads moved out of `lib/runtime/provider-protocol.ts` (its unused pidfile matcher is gone) into the bwrap provider's own `apps/fleet/bwrap-identity.ts`. The protocol states the rule abstractly: identity is provider-private in `stateDir`, and liveness and `stop` prove the requested generation terminated, never by a reusable identifier alone. `ProviderOkResponse.pid` stays an optional diagnostic. The bwrap launch record is now validated as strictly as the removed shared reader was, and bwrap's stop-proof and PID-reuse behavior has tests (`kxk8`).
- Wire vocabulary: callback error codes and their HTTP statuses come from one table (clone lifecycle routes now answer `invalid_identity` with 401 and `generation_obsolete` with 409), callback limits derive from the shared SSE constants, edge `stream_reset` carries its reason, and the never-produced `subagent_event` frame and unused wire types are gone; the stats `SubagentInfo` type is renamed `SubagentFileInfo` (`jnhk`).
- Swept dead exports and stale planning comments across fleet, session and wire (including the uncalled `annotationUpdate`/`annotationReanchor` methods and a duplicate sha256 helper); the callback transport prunes revoked enrollments and idle pumps and answers pair status from a per-workspace index (`7hz6`).
- Provider contract doc (`gmsp`): `docs/provider-protocol.md` describes the provider protocol from the code (ops including `preflight` and `list-sessions`, request and response envelopes, error codes, generation, handle and identity rules, capabilities, the profile union per kind, the preparation layout, the callback env handoff, security notes, versioning, and how the in-process host runtime differs from executable providers). References to the clone design, plan, ledger and architecture documents that no longer exist, and their `P<n>.<m>` phase tags, are gone from code comments, tests, the release preflight script and `docs/release.md`; the release preflight no longer carries exemptions for those files.
- Provider profiles are a union keyed on `provider` (`bwrap`, `kubernetes` or `host`) from one kinds list in `lib/runtime/provider-protocol.ts`: `tools`/`network` belong to bwrap, `image`/`namespace`/`context` to kubernetes, and a field on the wrong kind is a config validation error that drops the profile with a warning (a kubernetes profile no longer takes `tools`; remove it) and an `invalid_request` on the provider protocol. The fleet decides clone preparation, wake resume, fetch-into-project, secret resolution, and the default clone source from a static per-kind capability declaration (`preparation`, `volumeFleetVisible`, `secretResolution`) instead of provider names; the public profile shape is unchanged (`vyx1`, `xjv5`, `62np`).
