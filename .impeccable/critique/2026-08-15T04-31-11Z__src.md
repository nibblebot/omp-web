## Design Specificity Verdict

**LLM assessment (A): Authored for this product — high specificity (9/10).** The roster row is unambiguously daemon supervision: an eight-status dot ladder (spawning/connecting/session/resolving pulsing accent; ready green; reconnecting amber; error red; asleep flat ring) with paired text labels, git porcelain counts as `+ ~ - ?` glyphs, branch-as-title worktree rows, wake-then-attach, two-click armed kill, and a detail popover with live stderr. Steering vocabulary (steer vs follow-up queue chips, Enter vs Ctrl+Enter) encodes the product's fan-out concept. Supervisor density controls (consolidated run rows, three tool-card views, Ctrl+O) scale to N sessions. The only generic-adjacent layer is the pixel-art mascot/pet, but it executes as brand identity, not template.

**Deterministic scan (B): CLI detector clean — exit 0, zero findings across 84 src files** (sanity-validated against a deliberately bad control file → exit 2 with correct hits, so the clean result is genuine). Coverage caveat: several CLI matchers need literal kebab-case CSS and cannot see `var()`-indirected token usage, which is this codebase's dominant style.

**Browser overlays (B): injection succeeded; overlays visible in tab `critique-b`.** The overlay scan flagged: `overused font: roboto (42–69% of text)`, `flat type hierarchy (9.6–14px, ratio 1.5:1)`, `monotonous spacing ~0px (100%)`, `pulsing status dot`, `glowing shadow accents (#4ade80)`, `cramped padding` ×1, `undersized functional text` ×11–15. Judged against DESIGN.md doctrine, most are **false positives by design**: the Zero-Asset Rule mandates the system stack (Roboto appears via system-ui fallback on this machine); the small type ladder, flat spacing, status pulse, and status glows are all committed doctrine. The corroborated real signal is **undersized functional text** (9.6–10.5px micro type on ~11–15 elements) — it converges with A's accessibility findings (icon buttons ≈13×20px, micro text at the edge of comfortable). One detector defect observed: result serialization crashes on a circular `_impeccableOverlay`→`_targetEl` reference (`[impeccable] scan failed` in console), though banner and overlays still render.

## Overall Impression

A genuinely authored ops console with a strong committed world, executed with rare discipline — clean detector, coherent tokens, status language that never cries wolf. The weaknesses are not aesthetic; they're **safety-model inconsistency** (one-click destructive paths beside two-click kills), a **first-run dead-end** (disabled Send with no inline path to attach), and **chrome density creep** in the status bar. The single biggest opportunity: make the danger model and the first-run attach path as deliberate as the rest of the status language.

## What's Working

1. **The status-dot ladder** — eight lifecycle states in one 8px atom with glow/pulse semantics, always paired with a text label; the "signature atom" claim is earned (verified live: asleep ring, ready glow).
2. **Supervisor density controls** — three tool-card views + Ctrl+O + consolidated run rows + collapsed tails; the UI scales to watching N sessions.
3. **The roster row** — repo grouping, branch titles, porcelain counts, wake-then-attach, armed kill, live stderr popover; a complete per-daemon surface in 240px.

## Priority Issues

1. **[P1] Inconsistent danger model.** Sidebar stop/remove arm on first click (`DaemonSidebar.tsx:149-181`), but `/drop`, `/clear`, `/fresh`, and the "New session" button dispatch instantly (`PromptBox.tsx:275-277`). Worse: the arm state is a per-row component signal that roster broadcasts can remount away mid-confirm — the two-click language can silently reset between clicks. *Fix:* arm-once confirm for destructive slash commands when the session has history; hoist arm state module-level like `activatingIds`. *Command:* `$impeccable harden`
2. **[P1] First-run dead-end.** The only attach guidance is muted gate text ("no daemon attached — pick one in the sidebar", `PromptBox.tsx:283-294`); the attach affordance lives only in hover titles. *Fix:* make the gate pill a button that opens + highlights the sidebar, or surface attachable daemons as chips in the empty state. *Command:* `$impeccable onboard`
3. **[P1] Mobile sidebar occludes the composer.** At 390×844 the overlay covers ~61% of the viewport with no scrim or click-outside dismiss; chips and gate text render clipped underneath. *Fix:* add the Backdrop scrim + outside-dismiss at ≤720px, or cap width at `min(200px, 70vw)`. *Command:* `$impeccable adapt`
4. **[P2] Settings shows 12 sections at once** — the one true cognitive-load failure; search field is placeholder-only. *Fix:* group tabs (Appearance / Agent / Infrastructure) or default to an essential view. *Command:* `$impeccable distill`
5. **[P2] Status bar chrome exceeds the doctrine.** 9 segments + badges at rest; ⤢/☰ glyph-only; icon hit targets ≈13×20px (below 24px guidance); overlay-confirmed 9.6–10.5px functional text on a dozen+ elements. *Fix:* overflow "⋯" menu for pet/ⓘ/⚙, real aria-labels, larger hit targets. *Command:* `$impeccable polish`

## Persona Red Flags

**Alex (power user):** "New session" sits directly beside Send — a stray click mid-steering fires `/new` with no confirm. `Ctrl+O` is not suppressed while a modal is open (unlike `Ctrl+R`). No keyboard shortcut to attach a daemon; Tab-through-roster is 20+ stops.

**Sam (accessibility):** Roster rows are keyboard-activatable but the row `role="button"` contains nested buttons (■ ✕ ⓘ) — the live ARIA snapshot flattened them into one giant button name. Icon buttons ≈13×20px. Message hover toolbar is `opacity: 0` until hover/focus-within — keyboard users tab through invisible controls. Contrast passes AA (worst pair 4.88:1); micro type at 9.6–10.5px (detector ×11–15 hits) sits at the edge of comfortable.

**Riley (stress tester):** Armed stop/remove can be silently reset by a roster broadcast landing between the two clicks (per-row signals remount; the module-level `activatingIds` pattern exists for exactly this reason but confirm flags don't use it). Empty states are excellent throughout ("No models available", "no daemons — press + to spawn one", "(no stderr output yet)"). Long paths ellipsize with `title` fallbacks.

## Minor Observations

- Spawn dialog's primary action uses the accent-*wash* treatment while Send is the only full-fill accent — two "primary" idioms.
- Queue chips aren't a live region; a queued steer mid-flow has no announcement beyond the count chip.
- `msg-notice` renders info and warning identically; the `level` parameter is visually unused.
- Collapsed repo group headers hide their daemons' status entirely — no aggregate health dot.
- Daemon-detail modal stderr doesn't auto-refresh while open.
- Glyph labels ⤢/ⓘ/☰/⚙ rely on `title`; aria names come from the glyphs themselves.
- Disabled-Send reasons are only visible on hover.

## Questions to Consider

1. Should the console offer a split-view (roster + live stream) for the actual N-session supervision pattern, or is modal-attach the deliberate focus choice?
2. Is the text-command surface's speed-for-safety trade (`/drop` in one Enter) intentional — and is it visible to a tired operator at 1am?
3. Does the pet/mascot layer earn its screen space in a deliberately instrument-panel UI, or is it the first cut in a density pass?
4. Should settings be organized around operator tasks ("make the agent faster") with the 12-tab schema as advanced mode?
5. If daemons are disposable and resume from `.jsonl`, why is remove-from-roster two clicks while `/drop` is one?
